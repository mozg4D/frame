# 3D Printer

Follow the root AGENTS.md and plugins.md. Keep runtime code in this directory and plugin checks in tests/index.mjs. The standard and stress runners discover these checks through the plugin catalogue.

- A printer is an ordinary independent scene object; creation must allow multiple instances. Parameters, transforms, visibility, animation, Undo and HASH belong to the core editor.
- Local +Y is the build direction. The volume is X/Z [-500,500] mm and Y [0,1000] mm. Exclude fragments outside the volume and on the bed from surface-angle warnings. Share the core GPU device, evaluated geometry and raster depth; never retain a CPU triangle mirror.
- The current warning is an immediate face-angle preview, not a slicing/support result. The core derives the visible-side geometric normal from raster derivatives without reading supplied shading normals or winding. For a closed object viewed from outside, this is its outward visible side. Open zero-thickness faces are classified on the viewed side; their material interior cannot be inferred. Top faces must not be classified as undersides. Respect mirrored/rotated frames and visibility. Bed exclusion includes 0.001 mm tolerance for Float32 projection reconstruction.
- Author the printer icon at native 32x32 pixels without scaling, using a subdued color. The layer controls have an 8 px gap after Layer position through the declarative breakAfter field.
- Raw plane intersections now feed closed GPU section contours, repair, even-odd classification, union and bounded simplification. Machine output, physical-width offsets and the full planner remain deferred.
- Attributes contain only editable controls and requested spacing. Diagnostics stay in the API/developer data.
- Each test checks observable editor or GPU behavior and useful completed-operation latency. Tests are visible by default; keep input inside Playwright and isolate native pointer-lock checks in headless Chromium. Do not treat missing WebGPU as a pass.

## GPU closed section contours (2026-10-24)

Runtime remains one plugin.js, the native icon and the manifest. The native triangle-span count/emit stage still intersects evaluated GPU geometry in printer-local coordinates, independently of supplied normals/winding. Its layer-scan alternative is retained for benchmarking. Layer 1 uses Initial layer height / 2; subsequent centers use Initial layer height + (zeroBasedLayer - 0.5) * Layer height, with half-open triangle Y intervals. X/Z clipping and physical-width insets are still deferred.

GPU vector passes deduplicate coincident segments within each evaluated solid occurrence, pair nearby endpoints within 0.02W, weld each reciprocal pair at its midpoint, and close each remaining nonbranching chain between its own two free ends. A straight closing segment is a geometric repair convention, not recovery of unknowable missing surfaces. Separate islands are not joined. Raw endpoint clusters use up to eight rounds of reciprocal nearest pairing, locking each accepted pair before considering the remaining endpoints. No endpoint receives two neighbors. Remaining chains use the same explicit closing convention. Unresolvable union-boundary assignments still reject the whole job.

Adaptive LDNI-inspired interval slicing uses sorted source-event ray levels in the printer-local X/Z plane. Each depth sample retains its geometric tangent, derived from the intersection segment rather than supplied normals. Workgroups sort at most 1024 active intersections per ray. Even-odd owner intervals and their union determine the boundary; adjacent depth-order crossings introduce exact adaptive levels inside a strip. Above/below event-ray parity creates horizontal boundaries. Continuous visible spans of the same source segment merge before loop assembly, while separated spans stay separate. A packed 128-bin height index bounds active-ray queries. No full-bed image, voxel volume or CPU coordinate mirror is created. The design follows the interval/ordered-sample principle of Zeng et al., Efficient slicing procedure based on adaptive layer depth normal image (2011), https://doi.org/10.1016/j.cad.2011.06.007; it is an independent GPU implementation, not a reproduction of the paper's complete LDNI/normal model.

Raw deduplication, reciprocal endpoint repair and bounded chain closure remain shared with the exact vector path. Batches containing a layer above 4096 raw segments use exact vector refinement directly to bound sparse-ray fragmentation cost. Ray overflow, excessive event/index/output storage, interval fragmentation above the compact source count plus 64, and unresolved boundary assignments invoke that same exact vector arrangement for the affected batch. Temporary interval resources are retired before refinement. Loop assembly, colors, simplification, cancellation and atomic publication use one common path. Status exposes representation: adaptive-ldni, intervalFallbacks (batches routed to exact refinement) and the latest intervalStats (rays, compact sourceSegments, boundarySegments). Counter readback and completed topology timing include rejected interval attempts as well as refinement. The fallback preserves bounded behavior on dense or damaged geometry; the method does not promise universal linear cost.

The accepted coherent deviation limit is 0.2W. It permits a shared displacement of a complete family of neighboring trajectories; it does not authorize independent 0.2W simplification of each bead or certify deposited coverage. Current output remains thin section boundaries, with exact affine ray depths and the existing stricter 0.02W contour simplification. Physical-width trajectories and joint bead allocation are deferred. No arbitrary new sampling grid or independent per-line widening is introduced.

Boundary successors use closest endpoints and filled-left turns. Bounded claim/rematch passes reconcile near-coincident endpoint clusters into one-to-one links. A residual augmenting search visits at most 128 assignments per path and 1048576 candidate edges per layer. If endpoints remain unmatched, one directed-chain repair connects each free tail to its own free head, rejecting crossings with unrelated boundaries. Matching is then repeated once; unresolved boundaries fail atomically. Each closed loop's signed area determines its kind: exterior/island boundaries are green-teal (0.32,0.76,0.59), hole boundaries orange (0.96,0.48,0.24). Preview uses native one-physical-pixel line-list splines, without physical ribbon rendering or polygon fill. The warning shader and three colored box axes remain independent.

Greedy contour simplification checks every skipped source vertex against each replacement segment and rejects proper crossings with source boundaries. Its geometric tolerance is at most 0.02 times Line width; it retains at least three vertices per loop. Repair/union intentionally changes malformed/overlapping input geometry, so this approximation tolerance describes simplification of the repaired boolean boundary, not an accuracy claim for missing geometry, extrusion width, swept coverage or adjacent deposited strips.

Coordinates remain on GPU during slicing. CPU reads only layer/output/repair counters for bounded allocation and control. Status reports rawSegments, segments, repairs (inserted chain-closing connectors), simplificationTolerance, topology: closed-even-odd-union, completed wall timings, peakGPUBytes, metadataReadBytes and triangleVisits. Explicit inspect reads at most 4096 final segments from one layer, returning positive x/y/z/width endpoint pairs plus one kinds entry (outer or inner) per segment. Optional offset/count paginate a dense layer; totalSegments and inspectionOffset describe the returned page. Omitted count reads the remaining layer only if it fits the 4096-segment inspection bound. Internal GPU records use signed second-endpoint width for kind; inspection normalizes width. No derived buffers are saved in HASH.

Limits: 4096 layers, eight million raw/final segments, 256 evaluated solid occurrences, 65536 raw edges per layer, at most 126 interior split parameters per source edge, and eight endpoint-assignment repair passes. Exact vector refinement has quadratic worst-case layer cost; ordinary batches are bounded to 256 million raw edge pairs; a single denser layer runs independently within the per-layer limit, and dispatch windows contain at most roughly 16 million pair queries and at most 32 MiB raw/64 MiB closed/intersection bindings. Exceeding a bound is an API-only error, with no partial result. peakGPUBytes includes all owned scratch and retained output. Conservative packed GPU interval/cell lists accelerate exact vector queries (64 height bins for ordinary batches; 128x128 or 512x512 coarse cells for dense layers). They do not approximate filled geometry. Index storage is capped at 64 MiB, with overflow rejected before allocation. GPU pointer doubling finds closed-loop roots; parallel chord proposals retain the same vertex-deviation and crossing checks before greedy simplification. There is no promise of real-time slicing for arbitrarily dense layers.

Jobs publish atomically after GPU completion. Cancellation, scene/device/source/visibility/frame/Line width/layer-height changes reject stale output and release unpublished buffers. Preview controls and Overhang angle retain geometry. Perimeters and Min path length remain deferred planner settings. First nonempty success initializes Finish; later success preserves/clamps it. Start/Finish choose the displayed inclusive range. Positive Layer position selects one layer; changing either range endpoint resets Layer position to 0 in the same native UI/API/Undo transaction, via the manifest's generic parameterResets rule. An explicit Layer position in the same API patch takes precedence.

Run npm run test:slicer, npm run test:slicer:corpus, npm run test:slicer:performance and standard/stress suites. Focused checks verify actual UI edits and colored pixels, closed directed loops/areas, nested parity, overlapping/coincident/shared-edge unions, damaged chains, winding/texture/frame independence, curve deviation, cancellation, HASH and latency. The corpus includes the unchanged incoming STL.

## Remaining slicer specification and architecture

The following is deferred backlog from the previous request, retained for future stages only. The implemented stage above does not implement physical-width perimeter planning, build-envelope clipping, path-length filtering, swept coverage or machine output. Existing section repair and even-odd/union are prerequisites rather than the full planner.

### Ownership, coordinates and scale

- Own implementation in WebGPU/WGSL, without importing Cura, Arachne, Clipper, Three.js or another slicing/geometry runtime. Reuse native mathematical concepts and the shared core GPU resources rather than claiming the concepts are novel.
- Each printer is independent and may be arbitrarily translated/rotated with its ready-made assembly. Every slice, build limit and overhang computation uses that printer's local frame, with local +Y up. Never assume world Y is the build axis.
- Start with perimeters only. Example large-format envelope: 4000x4000x4000 mm, W=2 mm nominal extrusion width/nozzle, 1 mm layers. Speed and bounded RAM/VRAM are essential.
- Use the current evaluated GPU geometry, including transforms, instances and generators. No permanent CPU triangle copy and no parallel scene graph. Ignore supplied polygon normals and triangle winding. Tolerate duplicates, small cracks, degeneracy and moderate corruption with bounded repair; an arbitrarily open shell has no uniquely determined solid interior.
- Ignoring winding makes nested closed shells ambiguous: geometry alone cannot distinguish a cavity from a redundant contained solid. The implemented convention is even/odd filling inside one evaluated solid occurrence and union across separate occurrences, validated against the incoming STL and nested-shell fixtures; do not infer fill intent from flipped normals.
- Print only inside the printer. Clip filled section regions, then ensure the entire deposited strip stays within the build envelope; clipping triangle candidates or center lines alone is insufficient.

### Proposed computation pipeline

1. GPU bounds and a coarse hierarchical height/slab index select triangle candidates for bounded batches of layers. Avoid scanning every triangle for every layer and avoid storing a full triangle-times-layer table.
2. Triangle/plane intersections produce vector segments. Use consistent half-open vertex/coplanar-edge rules, GPU compaction and a spatial index to assemble contours. Resolve filled areas independent of source normals, then union assigned solid regions and clip to the printer.
3. Retain vector boundaries as geometric truth. Use sparse adaptive 2D distance/nearest-boundary tiles to locate local thickness, opposing boundaries, medial branches and the places where perimeters meet. Refine results against vector segments; a raster/JFA approximation alone cannot certify topology or contour tolerance.
4. Jointly distribute bead count and width across neighboring perimeter cycles; do not repeatedly offset by W and patch the final tiny gap afterward. Use the local thickness/medial graph to distribute residual space before it becomes a thin final path.
5. Build a graph of feasible continuous connections and choose short travels with bounded optimization. Verify actual swept-strip coverage, intersections, voids and double deposition. Exact global travel/path-count optimality is not promised.
6. Simplify final vector paths while checking deposited-strip boundary error and joins. Stream completed results/output in bounded batches. CPU coordinates jobs, small metadata and serialization; expensive geometry remains GPU compute.

A full-bed fine texture is unsuitable: 4000/0.04=100000 cells per side at the nominal 0.02W tolerance for W=2 mm, or 40 GB for one float32 scalar channel of one layer. A full-volume high-resolution SDF/voxelizer is also unsuitable as the primary representation. A spatial hash is an accelerator, not the complete slicing algorithm.

### Path, width and corner rules

- Minimize total travel, number of separate trajectories and output segment count. Prefer continuous perimeter spirals. Prefer clockwise traversal consistently, viewed from local +Y toward the build plane, because reversing traversal direction can expose printhead backlash as bands. Topology/necessary local return motions may require explicit exceptions.
- Prefer approximately 45-degree planar connections between successive perimeter loops. This is not continuous-Z vase mode. Disconnected islands, holes or branches can require separate paths or another feasible connection angle.
- Width normally lies in 0.6W..1.5W. A 1.5W-wide strip gets one 1.5W bead; a 1.6W-wide strip gets two 0.8W beads. Coordinate bead-count transitions along the shape so noise near a threshold does not generate short alternating branches.
- For an isolated narrow feature with total available width 0.6W..1W, still extrude 1W to avoid a fragile wall. This is an intentional local exception to surface accuracy; it does not prohibit two 0.8W beads inside a 1.6W region. Do not invent a geometric tolerance guarantee for this widening.
- Filter out an entire ordinary extrusion trajectory whose total length is below 3W. The user prefers a small void to a short micro-path. Minimize sub-1W segments and avoid short width/count-transition regions, while distinguishing a whole trajectory from segments needed to approximate a curve.
- A single-perimeter loop overlaps start and finish by 0.2W. Distribute the final residual space among the last two or more perimeters.
- Normal geometric target: 0.02W maximum boundary error and similarly good joins between neighboring strips. At sharp bends a larger deviation is acceptable when 0.02W would require excessive segment counts. The exact relaxation policy still needs definition and validation; prioritize well-joined printable lines over microscopic detail.
- For a corner sharper than 45 degrees: approach, expand sharply up to 1.5W touching both boundaries, taper toward the tip to 1W, continue at 1W until available space narrows to 0.6W. On the return, apply the requested 0.1W pressing over 1W length so the nozzle does not pull the tip off the bed, return to the expansion point and broaden as needed to avoid voids. Preserve this explicit exception to ordinary minimum length/width constraints. The physical meaning of 0.1W in the motion/extrusion representation still needs to be made precise; the user clarified its purpose as light tip hold-down during return, not ordinary gap filling.
- Constant volumetric flow is the intended future process model, with travel speed varying with bead width. Do not implement process/pressure control now; first show correct geometric trajectories. Physical corner behavior needs print samples later.

### Rendering, warnings and controls

- Expect extremely many segments. Render directly from compact GPU buffers with bounded visible-layer work and minimal draw overhead; never create an object or CPU-expanded quad array for each segment.
- Camera-facing planar rectangles with straight butt ends, no round caps. Render a strong brightness gradient across each strip: a dark edge, most of the rectangle bright and nearly uniform. Display geometry is separate from the real swept strip used for coverage validation.
- The editable Overhang angle controls both the geometry-warning shader and future toolpath colors immediately, without reslicing solely to change the angle. Do not hardcode 45 degrees; it is the default.
- For sliced paths, compare actual deposited strips against support from the preceding layer in printer coordinates. For a threshold below 90 degrees, allowed lateral growth is layer height times tan(threshold); at 45 degrees it equals layer height. The bed supports the first layer. This is distinct from the immediate pre-slice face-angle preview.
- Add a normal Attributes Manager Slice button at the top of printer attributes when a real slicing operation exists. The user also spelled it splice; use the ordinary English Slice label. Display extremely short slicing progress immediately to the left of that button, never verbose logs. This is the user's explicit future exception to the general Attributes-no-progress rule; it is not authorization to add progress to other controls.
- On the first successful slicing, initialize Finish layer to the actual last layer. Subsequent successful slicing preserves the user's chosen finish layer; define clamping if it exceeds the newly generated range. Failed/cancelled jobs do not consume first-success initialization. Preserve the small gap following Start layer / Finish layer / Layer position.

## Transform and warning feedback

Only the last active eligible printer draws the immediate surface-angle warning; other printer helpers and section previews remain independent. Selecting a mesh or empty space preserves that printer. The local +Y build direction follows its evaluated frame. The blue helper points toward local -Z, starting with the other colored axes at (-500,0,500), inside the box.

Slice is required for initial sections. A common printer/source assembly transform preserves local contour buffers. Relative-frame changes to a completed section job coalesce a refresh after native transforms finish; stale previews are hidden meanwhile. Geometry, visibility and slicing-parameter changes still require explicit Slice. Retiring/cancelling a printer clears its refresh timer. Use scene.capture(...).contentSignature and scene.transforming through the generic core bridge; do not inspect internal editor selection or maintain geometry copies. tests/feedback.mjs verifies rendered pixels and completed latency for these paths and runs through tests/index.mjs.

The topology revision adds focused numerical regressions for infinitesimal side classification, reciprocal endpoint clusters and augmenting boundary assignment. Runtime geometry remains entirely GPU-owned. Counter-only allocation and the existing simplification tolerance are preserved.
