# Cut implementation plan and geometry boundary

A bounded standalone subset of step 5 now exists in `linear-regions.js`, documented in [LINEAR-REGIONS.md](LINEAR-REGIONS.md): continuous explicit linear motion/filled polygon checks, holes, head-reference Avoid and active disk No-cut. It accepts already-qualified local physical geometry only. Native region projection, full source capture, work-area/travel qualification, routing and No-cut splitting/restarts remain pending. No runtime API or HASH records are added.

An isolated subset of step 4 now exists in `linear-paths.js`, documented in [LINEAR-PATHS.md](LINEAR-PATHS.md): physical rigid-basis admission and explicit open Cut/Mark and simple closed Mark work intervals. It is unloaded and takes supplied linear geometry. Native source capture, closed Cut compensation, leads, exclusion regions, travel, complete jobs and G-code remain pending. It does not qualify the runtime generation boundary.

1. Qualify this native authoring foundation: creation/Top orientation/axes/pivot, ordinary scale and rotated frames, multiline fields, native tags, CAS/Undo/duplicate/HASH and latest-applied defaults. No solver or route is loaded.
2. Add a bounded shared evaluated planar-source capture contract. Current `context.scene.capture` borrows canonical evaluated mesh GPU resources, not a qualified spline/profile catalogue. Frame's native source cages, evaluated transforms, instances, generator consumption and effective visibility must supply automatic spline and Extrude profile discovery. Report exclusions through API. Define/test planarity tolerance in Cut-local millimetres; do not silhouette arbitrary tilted bodies or clip closed parts into artificial boundary cuts. Tagged regions cannot also cut; consumed Extrude source/history cannot duplicate output.
3. Reuse FrameGeometryKernel's native Outline implementation in index.html (`frame-geometry-kernel`, dispatched through the FrameGeometry worker's `outline` operation). The current public FrameGeometry.outline(n,distance,segments,inner) is an editor mutation with a source-cage freshness check, not a pure cancellable CAM service. Expose the existing kernel through a narrow non-mutating shared job bridge rather than calling the UI mutation or copying an offset engine. Its arrangement budgets and numerical gap/ambiguous walk failures are not proof of CAM suitability. Qualify cubic error, self-intersections, close contacts, nesting and narrow features before advertising accuracy.
4. Construct verified local paths: closed Cut centerlines offset half the full Line width toward waste; classify outside/holes geometrically; all closed paths CW from the head side. Open paths remain uncompensated without special lead-in; Mark uses original lines without compensation or burning arcs. Lead-in means start distance from the source contour, not radius or length. Find safe tangent arcs jointly with entry points, full cut width, neighbors and boundaries. No added lead-out, bridges between contours or common-cut optimization.
5. Project actual evaluated Avoid/No-cut regions with holes. Enforce area bounds for cuts, arcs and travel; Avoid wins overlaps and blocks head-reference motion. No-cut disables the tool with kerf-aware bridge preservation on every pass. Find safe restart arcs after bridges, or explicitly qualify a safe simple restart. No automatic height bypass or assumed head-envelope protection.
6. Build a deterministic legal route and improve actual total path length, choosing starts, open directions and order jointly. Complete holes and all their passes before outer release. Test legal baseline versus improvements and small known optima; never claim global minimum.
7. Add asynchronous revision-fenced jobs, cancellation, owner retirement and atomic publication. Capture native scalar inputs plus synchronous authoring epoch/revision, recheck after every await, and also qualify evaluated geometry/resource identity. Camera navigation and sequence cursor must not invalidate a physical fingerprint. Never regenerate on every gizmo step. No Save for stale, failed or empty output. Generation failures use only a red native owner name in UI, with API details and recovery clearing the error.
8. Introduce one ordered sequence for preview, time and saved text: travel, on/pierce, tangent arc, work, off, bridge and completion. Expand passes explicitly. Start/Finish once per job, on/off per active interval rather than tessellation segment. Define machine dialect, modal units/absolute-relative/arc-plane/feed/tool handling and any template language. Keep unknown macros opaque; do not invent their movement/time. Arbitrary block technological moves need safety analysis before publication. Estimate recognized motion/dwell; expose unsupported durations as API limitations.
9. Implement G-code position as exact saved line number: 0 before first line, N after line N, including blank lines/comments/user blocks. Use indexed sequence states for efficient scrubbing, with no geometry rebuild. Add file Save only for a current nonempty sequence, with explicit API export and no machine transmission. Complete actual UI action placement/time display and recoverable error presentation.
10. Qualify original acceptance geometries and independent saved-file checks: complex cubics/holes, nearby parts, obstacles, multiple bridges/passes, rotated owners, all line/modal states, cancellation/stale races, HASH defaults provenance and resource retirement. Record actual error bounds, baseline/improved route lengths, timings and memory. Run standard/stress hardware gates and relevant heavy-scene benchmarks before release claims.

No runtime geometry tolerance, cut accuracy, route quality, time estimate or G-code dialect is implemented or qualified by the authoring milestone. The separate CPU work-interval module documents its own bounded numerical admission contract and exclusions; it is not runtime CAM qualification.
