# Контекст приложения

3D-редактор для больших треугольных сеток и spline patch моделей. Текущее приложение — один `C:/frame/index.html`: интерфейс и нативный WebGPU-движок встроены в файл; рядом могут находиться текстуры и пользовательские сцены. `import.html` — исторический самостоятельный прототип движка. Приоритет: скорость больших сцен, умеренная память, компактные файлы и простой код. Ngons не планируются.

**AI API/MCP — ответственность AI-разработчика приложения.** В процессе любой задачи, если управление, диагностика или проверка через API неудобны либо не хватает команды, AI самостоятельно дорабатывает `frameAI`, схемы, документацию и регрессионные тесты в рамках этой задачи. Не следует перекладывать развитие API на пользователя или обходить отсутствующую функцию параллельной моделью сцены. MCP остаётся тонким транспортом к тому же API.

## Ядро версии 1 и 2D-виды

- Первая версия выпускается только с ядром: каноническая HASH-сцена, GPU-данные, виды, моделирование, материалы, анимация и встроенная библиотека моделей. Вкладка Modules и вход в 3D Printing убраны. Runtime остаётся одним `index.html`, без системы загрузки модулей и внешних JS-зависимостей.
- Адаптивная сетка и ортографическая навигация входят в ядро. Top смотрит вдоль −Y, X вправо и −Z вверх; Front — вдоль −Z, X вправо и Y вверх; Right — вдоль −X, −Z вправо и Y вверх. У всех четырёх видов независимые камеры. Короткий клик СКМ (до 350 мс, максимальное смещение до 24 CSS px) переключает один/четыре вида под курсором. Pan начинается с первого пикселя без ожидания порога; если отпускание распознано как короткий клик, камера восстанавливается до переключения видов. В 2D колесо и ПКМ масштабируют к точке под курсором, ЛКМ выделяет рамкой, короткий клик выбирает элемент. В перспективе прежние orbit и Alt+ЛКМ сохранены.
- Математика основана на `makeOrthoGrid` и `NavOrtho` [Frame r248](https://github.com/mozg4D/frame/blob/238944aab5a7b4aa0836297645b23005c3a2dde5/modules/editor.14694d2e39a34bf370f7.js#L14464), перенесена в нативный WebGPU. Основной шаг = 10^ceil(log10(140 × мм/пиксель)), мелкий в десять раз меньше. Интервалы считаются в CSS-пикселях, данные сцены всегда в миллиметрах. Цветные линии обозначают оси проекции. Перспективные девять линий осей/сетки остаются прежними. Во viewport видны FPS и HUD памяти: названий видов, шага сетки и при движении гизма показывает расстояния по единичным осям.
- Линии генерируются только внутри окна; их число ограничено экранной плотностью. Вычисляем фазу в Float64 и загружаем малые локальные NDC-координаты, а не далёкие Float32-позиции. Индексы цикла локальные: огромный pan и очень мелкий шаг не приводят к зависанию при `n++` выше точности целых Float64. Zoom ортографии не требует GPU ray-picking: экранная привязка аналитическая и не зависит от глубины поверхности.
- Единственный GPUDevice и одни буферы каждого mesh используются всеми видами. Активный вид сохраняет существующие карты picking/hover. Неактивные виды используют готовое изображение своего canvas и только собственную depth-текстуру; при навигации другого вида повторно не рисуются. Правка сцены/selection/видимости обновляет все видимые виды. Ресурсы скрытых видов освобождаются. Ортографические pipelines компилируются при первом открытии 2D; шейдер перспективы имеет статическую специализацию, без динамической проверки проекции на каждую вершину.
- Камеры — исходные данные вида, сетка и её линии — вычисляемый кэш. Новых TYPE и адресов HASH не добавлено: используется существующая запись камеры Float64. Первые 12 значений — камера перспективы; при необходимости дописываются по три числа (центр U/V и половина высоты в мм) для каждой 2D-камеры, индекс активного вида и режим один/четыре. Всего 23 числа; при отличающихся от defaults режимах shading добавляются четыре индекса режимов, всего 27. Чтение записей длиной 12/23/27 поддерживается. Фиксированные ориентации, FOV, линии и GPU-кэши не сериализуются. Если 2D-камеры по умолчанию, активна перспектива и один вид, хвост опускается. Значения камеры актуализируются в `scene.records` при изменении вида; Save использует тот же владелец данных.
- Проверки: по 114 проверок 2D на native/fallback при DPR 1 и 2, включая storage-buffer и texture-backed геометрию, привязку wheel/ПКМ к курсору, pan, рамку, клики Vertex/Edge/Polygon, GPU connected picking, независимость камер, повторный HASH Open, крайний zoom/pan и отсутствие лишних кадров неактивных видов. По 79 проверок рендера, 63 hover, 171 рамки и 179 редактирования на native/fallback проходят. Повторный HASH-тест 64 небольших копий сохранил SHA-256 всех 128 GPU-массивов для обоих backend; внешних JS-запросов нет.
- FPS проверяем при существенных изменениях ядра: одинаковые сцена, камера, размер, режим и прогрев; фиксируем GPU-ms вместе с условным FPS. На RTX 2080 Ti, 100 548 288 треугольников, Solid, 1682×1178 попеременная проверка прежнего/нового шейдеров в одной GPU-сессии дала медианы 13,369 / 13,435 / 13,435 / 13,435 мс (около 74–75 условных FPS). Контроль после окончательной загрузки: 13,435 мс GPU, 1,1 мс CPU; ранее CPU был около 0,6 мс, поэтому CPU-стоимость отдельно отслеживаем дальше. Падения перспективного GPU-throughput этот замер не выявил. В Top реальной сцены проверены смена мелкого шага 1000→100 мм, pan и отбор 6 видимых meshes из 64. FPS относится к полному GPU-кадру активного вида; первое обновление четырёх видов выполняет дополнительную работу. Это не частота монитора и не гарантия одинаковой скорости для всех ракурсов.

## Трансформы, гизма и координаты

- По умолчанию включён объектный режим. Vertex/Edge/Polygon — взаимоисключающие кнопки; повторное нажатие активной кнопки отключает её и возвращает объектный режим. Выбор в Objects Browser и viewport использует одних владельцев сцены, включая группы. Объектный выбор не заполняет маски миллионов вершин: показываем гизму и жёлтый BBox, затухающий за 350 мс. Повторный выбор запускает вспышку заново; при выборе объекта или группы вспышка есть во всех режимах элементов.
- Плоские части гизмы строятся из той же геометрии `CURVE_GIZMO`, что и редактор Curves; общий тест попадания в треугольник. Пространственные части сохраняют исходные наборы Frame. Отдельного второго набора плоских вершин нет.
- Preview объекта использует сохранённые при старте world-матрицы, без восстановления всей сцены перед каждым pointermove; пересчитываются только изменённые BBox/uniform. События гизмы объединяются в один update на animation frame, отпускание применяет последнюю позицию. Coordinate Manager кэширует общий результат для всех полей; размеры по осям, совпадающим с rest BBox, считаются аналитически, прочая GPU-редукция откладывается до конца жеста гизмы.
- Во время трансформации каждый вид лениво кэширует цвет и depth неподвижных meshes. Следующий кадр восстанавливает их экранным проходом и рисует только меняющиеся meshes с корректным depth. Касающиеся/пересекающиеся по BBox соседи включаются в динамический набор для сохранения порядка копланарных поверхностей и линий. При изменении камеры/размеров/неподвижных объектов кэш обновляется; в конце жеста текстуры освобождаются. Цена — около 8 байт на видимый физический пиксель, без копий геометрии; при трансформации всей сцены сокращения геометрического прохода нет. Новых HASH-записей не требуется.
- В ядро перенесён контракт инструментов [Frame r248](https://github.com/mozg4D/frame/blob/238944aab5a7b4aa0836297645b23005c3a2dde5/modules/editor.14694d2e39a34bf370f7.js), без Three.js. Собственная математика Float64, колоночные матрицы, столбцы X/Y/Z/translation. Локальная матрица объекта задаётся относительно родителя; world = parentWorld × local. Группа и меш используют одинаковый контракт. Если одновременно выбраны родитель и потомок, delta применяется только к верхним выбранным корням. Переподчинение сохраняет полную world-матрицу, включая skew; Undo восстанавливает и родителя.
- Позиции меша — canonical rest geometry на GPU. После прежнего импорта координаты уже расставлены в сцене, исходные матрицы identity: переносить их в другие буферы не нужно. Трансформ целого объекта/группы обновляет только небольшой uniform, BBox и версии. Сохраняем полную аффинную матрицу, а не lossy TRS: nonuniform world scale повёрнутого объекта сохраняет shear. Отражённые матрицы из файла поддерживаются, однако интерактивный scale через ноль в отражение не переходит. Нормали используют inverse transpose и знак determinant. Identity/posed и perspective/orthographic имеют статически специализированные render pipelines; posed-вариант компилируется только при первом использовании.
- Правка элементов выполняется прежними GPU-масками; world delta переводится в rest-space как inverse(world) × delta × world. Picking, hover, рамка, ray tests и overlays учитывают world-матрицу. Для размеров в выбранных осях GPU редуцирует реальные вершины и возвращает лишь шесть чисел. Вычисление ленивое, сериализовано и кэшируется по selection/pose/geometry; устаревшие запросы отбрасываются. Постоянной CPU-копии геометрии нет.
- Пивот — отдельная локальная матрица относительно геометрического frame объекта; изменение пивота не двигает вершины и world-матрицу объекта. При отсутствии записи центр выводится из BBox. Перед первым объектным трансформом этот пивот фиксируется, чтобы центр не уплывал. Направления гизмы выделяются polar decomposition, без накопления skew в ортонормальном базисе. В группе пивот может быть общим для всех выбранных потомков.
- Гизма — исходная Frame «3 в 1» из r248. Перенесены исходные 35 наборов вершин/треугольников, цвета, прозрачность 0,5 и приоритеты попадания: центральная белая зона uniform scale, цветные полосы осевого move, светлые продолжения осевого scale, внутренние области move по плоскости и наружные четверть-дуги rotation. Номинальный размер 75 CSS px; 2D World использует исходную расширенную плоскую геометрию EXTFLAT=3,35, перспектива и Object — пространственную EXT3D=10. Белый экранный квадрат P и сектор SR появляются по тем же условиям перспективы/наклонных объектных осей; полных колец, стрелок и букв осей нет.
- Пространственные части отражаются к камере по трём знакам; на всё время жеста знаки фиксируются отдельно для каждого вида, чтобы гизма не перескакивала при вращении. World/Object меняет базис и плоский/пространственный вариант. В плоских Top/Right осевой scale Z учитывает направление −Z. Scale линейно связан с движением границы BBox и учитывает расстояние от пивота до дальней границы; uniform scale использует постоянную экранную диагональ жеста. Минимальный размер — малый положительный предел относительно исходной точности/мировых координат: визуально объект плоский, матрица остаётся обратимой. Лишний ход за предел не накапливается; обратное движение сразу увеличивает размер, в том числе новым жестом после HASH Open. Alt+осевой scale сохраняет явный skew; обычный world scale сохраняет возникающий shear. Порог 6 px, Escape/потеря окна отменяют жест; изменение одного пивота переиспользует геометрический кадр.
- Все четыре вида имеют собственную проекцию гизмы. SVG рисует исходные треугольные области без Three.js и без прохода по геометрии модели; hover повышает непрозрачность до 1. SVG ограничен границами своего viewport. Нажатие на гизму неактивного вида сначала активирует нужную камеру и затем начинает жест. Проекции кэшируются по камере, базису, пивоту и размерам viewport; в неподвижном состоянии DOM не пересоздаётся. Зоны попадания соответствуют видимым треугольникам и исходному порядку частей.
- Q включает квантование: move относительно старта, scale по изменению размера; шаг в 2D равен мелкому шагу адаптивной сетки, в перспективе одной единице отображения. Rotation: 10° при расстоянии от центра <102,5 CSS px, 5° при <205 px, далее 1°. Skew квантуется с шагом 0,1. S включает snapping: move к видимым вершинам в радиусе 9 CSS px, в 2D при отсутствии вершины — к сетке; размеры scale привязываются к шагу. Оси/плоскости ограничивают результат. При завершении перемещения одной вершины совпадение с другой вершиной того же editable объекта вызывает weld; трансформ целого объекта топологию не меняет.
- Vertex snapping — ленивый GPU compute: CPU отбирает экранные BBox-кандидаты, GPU проверяет видимость по depth, расстояние и стабильный vertex ID при равенстве. Выбранные объекты/вершины и скрытые объекты исключены. Readback — 32 байта результата; поиски сериализуются, промежуточные устаревшие запросы пропускаются. Полного CPU spatial index нет.
- P: короткое нажатие переключает редактирование пивота; удержание на время жеста временно включает его и возвращает прежнее состояние после отпускания. Scale при этом отключён. Auto pivot ставит общий пивот в дальний от камеры угол world BBox, геометрия остаётся прежней.
- Coordinate Manager связан с теми же транзакциями: Position, Euler rotation в градусах, Size по выбранным осям. World использует мировой frame; Object — родительский frame для Position/Rotation и оси объекта для Size/гизмы. Работают ввод чисел, scrub, Enter/blur commit, Escape revert; один жест — одна запись Undo. Нулевой/отрицательный ввод Size ограничивается тем же положительным пределом, что и гизма. Display unit меняет только числа/подписи; Rescale меняет физический размер всей сцены ровно один раз на корневых матрицах. Внутренняя единица — мм; nm/µm/mm/cm/dm/m/km поддерживаются без пересчёта GPU-массивов.
- Ctrl+жест целого объекта/группы создаёт независимую копию каждого descendant mesh, со своими canonical GPU positions/indices, и копию иерархии; копирование и движение отменяются одним Undo. Ctrl+жест элементов сохраняет прежнее копирование полностью выбранных треугольников; Shift+Polygon/Edge — прежний extrusion. История metadata дешёвая и ограничена 100 действиями; геометрическая история использует прежний GPU/RAM бюджет. Ctrl+Z — Undo, Ctrl+Shift+Z/Ctrl+Y — Redo. После новой правки redo освобождается. Топологические изменения пока перестраивают весь затронутый mesh.
- HASH: новых базовых TYPE нет. Добавлены только нужные сейчас адреса `matrix`, `pivot`, `units` (детерминированные ID `md5(frame.core.<name>.v1)`). `matrix` и `pivot` используют TYPE 6, по 12 Float64: три линейных столбца и translation, без постоянной четвёртой строки. 96 байт payload до упаковки; identity matrix опускается, выводимый default pivot не сохраняется до необходимости. `units` — TYPE 0, два байта индексов Display/Rescale; значение mm/mm опускается. World/inverse/rigid frames, BBox, GPU uniform и размеры — кэши, в файл не попадают. JSON отсутствует. На Open проверяются длины, конечные числа, обратимость и родительские циклы.
- Проверки трансформов покрывают обычные и texture-backed сетки, native/fallback: вложенные группы без двойной delta, неизменные побитно source buffers, move/rotation/skew/mirror, posed picking всех элементов, пивот, reparent, nm↔km rescale, numeric component edits, Undo/Redo, Ctrl-копии/cancel, GPU snapping и HASH round-trip affine + exact geometry. Дополнительно повторены render/hover/box/ortho/edits и SHA-256 всех 128 GPU-массивов HASH fixture на обоих backend. Точные отчёты — `work/engine-*.json` в текущем workspace. По 97 проверок трансформов прошли при DPR 1 и 2.

- Контроль трансформов на реальной сцене: 64 mesh / 100 548 288 tri, Solid, 841×589, RTX 2080 Ti. Предыдущий/новый surface shader чередовались на одних буферах: медианы 13,238 / 13,238 мс (около 76 условных FPS), CPU текущего кадра около 1,0–1,4 мс. Для текущего Front: 8,389 / 8,389 мс; близкой перспективы: 1,180 / 1,180 мс. После перемещения корневой группы все 64 mesh использовали posed pipeline: 12,517–13,238 мс в последующей прогретой серии, без дополнительной копии геометрии, tracked memory около 9344 MiB. Это не доказательство ускорения: серии зависят от частот GPU. Реальный ввод Position X +100 мм, перетаскивание оси мышью и Ctrl+Z проверены; геометрия и камеры восстановлены. Отчёт: work/transform-live-performance.json.

## Новая архитектура и HASH — первый этап

- Единственный исполняемый исходник приложения — `index.html`. Встроены UI, WGSL, движок и кодек HASH; загрузки отдельного `engine.js` нет. `tools/serve.py` и `tools/start-frame.ps1` — вспомогательный локальный запуск, а не зависимости HTML. Текущий адрес: `http://127.0.0.1:56116/index.html`.
- Функции старого Frame с GitHub переносятся постепенно, с пересмотром концепции. Совместимость с прежними файлами сейчас не нужна. Старый кодек целиком не переносим.
- `.hash` — каноническая адресная модель сцены в RAM. `scene.records` — Map адрес → тип и значение. Для геометрии значением служит дескриптор принадлежащего конкретному мешу GPU-ресурса с актуальным количеством элементов; CPU-копий массивов в этой Map нет. Сжатое файловое представление создаётся только на Save.
- Новое поле/тип добавляется только при появлении реальной функции. Перед добавлением проверяем: это исходные данные или вычисляемый кэш; кто владелец; нужна ли отдельная запись; можно ли использовать существующий тип; какая точность обязательна; как оценить размер и проверить точный round-trip. Произвольного контейнера «на будущее» нет. JSON внутри HASH запрещён.
- Первый этап сохраняет независимые полигональные меши, группы, infinite lights и порядок объектов, имена, родительские ссылки, видимость/включённость/свёрнутость, камеры и раскладку видов. Материалы, текстуры и именованные наборы полигонов теперь тоже сериализуются; анимация пока не входит в HASH; spline cage, параметры сплайнов, примитивов и генераторов уже сохраняются. Добавлены локальные аффинные матрицы объектов и отдельные пивоты, а также единицы отображения/рескейла. Правки элементов меняют canonical positions; трансформы целых объектов и групп меняют только матрицы.
- Файл — поток записей: TYPE uint16 + адрес 128 бит + длина полезных данных uint64 + данные. Заголовок 26 байт, числовые значения little-endian. ID сущностей сохраняются; адрес свойства = ID сущности XOR постоянный ID свойства. Отдельная запись задаёт текущую схему 1. Незнакомые данные отклоняются; миграций и legacy-reader сейчас нет.
- Используем только существующие базовые типы: 0 — байты/битовые флаги; 3 — Uint32 (версия и индексы); 4 — списки 128-битных ссылок; 5 — Float32 позиции; 6 — Float64 камера и аффинные матрицы; 7 — UTF-8 имена. Kind объекта задаётся байтом: 0 — group, 1 — mesh, 2 — infinite light. Три флага объединены в один байт вместо трёх отдельных заголовков. Значения по умолчанию опускаются. Эти виды записей обоснованы текущими данными, а не будущими возможностями.
- Старшие биты TYPE — обратимая упаковка, не новые смысловые типы сцены. Выбирается меньший результат: исходный массив, gzip или подготовка массива + gzip. Для Float32 подготовка сохраняет битовые паттерны через XOR по осям и байтовые плоскости; для индексов — предсказание внутри треугольника, ZigZag и varint. Квантизации, потери разрядности и изменения порядка геометрии нет.
- Каждая из 64 копий имеет собственные записи позиций и индексов. Даже одинаковая топология не объединяется в инстансы или общую геометрию. Отдельный gzip каждой записи не меняет независимое владение.
- В файл не попадают нормали, shading aliases, adjacency, рёбра, текущее временное выделение, hover, ID-карты, BBox-кэши и Undo. Они вычисляются на GPU при открытии. HASH загружается без повторного weld/cleanup: должны сохраниться каждый Float32-бит, индекс и идентичность логических вершин.
- Save блокирует изменение сцены на время операции; readback — staging до 4 MiB, временная CPU-память ограничена текущим массивом и его упаковкой. Прямое сохранение через File System Access пишет записи последовательно; Download хранит только упакованные Blob-части. Постоянного CPU-зеркала геометрии нет.
- Open сначала индексирует Blob без чтения файла целиком и проверяет все полезные данные, ограничивая память одним мешем. Только после успешной проверки освобождает старую GPU-сцену; затем читает и загружает меши по одному. Это два прохода по файлу ради проверки повреждений без одновременного размещения двух огромных сцен в VRAM. Каждый меш получает собственные GPU-ресурсы.
- Текущие ограничения: до 512 MiB декодированных данных на запись, до 100 000 объектов, до 1 000 000 записей. Расширять ограничения следует вместе с потоковой реализацией больших записей, а не снятием проверок.
- Обычный STL импортируется одним объектом в исходном масштабе, без массива копий и умножения координат. Для миллиметрового workspace намеренно маленький `tests/scenes/test.stl` остаётся маленьким; F выполняет явное кадрирование. Сохранённая старая нагрузочная матрица из 64 объектов находится в `tests/scenes/stress-mesh-100m.hash` и больше не создаётся при импорте STL.
- Кнопки Open, Save, Save As, Save Incremental и Download работают с бинарной сценой. `?scene=имя.hash` открывает соседний нагрузочный файл при запуске; обычный запуск `index.html` (HTTP и file://) открывает пустую сцену без объекта Scene (включая первоначальный UI до инициализации GPU), импорта STL и spline workers. Пустая сцена сохраняется и открывается как HASH с пустым списком объектов. Ctrl+O/Ctrl+S вызывают те же действия.
- Нагрузочный файл `test-64-x1000.hash`: 64 самостоятельных меша, 100 548 288 треугольников; 260 записей, из них 64 массива позиций и 64 массива индексов. Размер проверенной сборки — 662 854 868 байт (около 632 MiB) против 1 809 840 693 байт полезных исходных данных. Save около 67 с, проверка и открытие около 29 с на текущем ПК; это единичный прогон, не универсальный benchmark. Разные GPU-порядки вершин при повторном STL-импорте могут немного менять сжимаемость.
- Верификация: SHA-256 всех 128 GPU-массивов до Save и после Open совпали; восстановлены ID, имена, иерархия, флаги. Проверены storage-buffer и texture-backed варианты, сохранение после Ctrl-copy топологии, последовательный writable Save As и Download, отказ на повреждённом файле с сохранением текущей GPU-сцены. После Open нет постоянных CPU-массивов геометрии. 179 проверок редактирования прошли на каждом из native/fallback вариантов шейдеров.
- Перед добавлением альтернативной Float32-упаковки проверен словарь координат: на реальном массиве он дал 5 493 117 байт против 5 171 101 байта у текущего XOR + gzip, требуя больше временной памяти. Вариант отвергнут; новый TYPE/декодер в приложение не добавлялся.

## Сплайны, spline patch и библиотечные примитивы

- Реализованы cubic Bézier splines и общий конвейер **spline cage → resolver → surface builder**. Extrude, Lathe, Sweep, Spline Patch и объёмные примитивы создают обычный cage: вершины Float64, относительные ручки `ha/hb`, сегменты, последовательности, soft/boundary и угол аппроксимации. В surface builder не передаются тип генератора, профиль, ось вращения или иные семантические подсказки. Семейства translate/ruled определяются только по контрольным точкам границ.
- Основа — алгоритмы Frame r248 из `modules/editor.14694d2e39a34bf370f7.js` и `surface-builder.0312b7b82f7796e0aedb.js`: угловая аппроксимация кривых, resolver, плоские контуры с отверстиями по even-odd, пространственные клетки с 2–5 сторонами, Extrude с плоскими/круглыми fillet, Lathe с полюсами, Sweep с parallel/tangent transport. Рендер Three.js не переносился; используется небольшой Float64 math adapter. Скалярный cubic evaluator общий с Curves.
- Ядро сплайнов и шрифтовые данные встроены в `index.html` как неисполняемый текст. Ядро разбирается при первой потребности; inline workers и дополнительные GPU pipelines создаются лениво. В полигональной нагрузочной сцене spline workers не запускаются. Дополнительных JS-файлов и внешних запросов к библиотекам нет.
- Регулярные четырёхсторонние translate/ruled поверхности используют исходные математические формулы в одном пакетном WebGPU compute-проходе. Общие вершины и образцы сегментов получают единые logical ID; GPU заполняет только внутренние позиции, границы сохраняются каноническими. Разбиение учитывает поворот нормали внутри патча, противоположные стороны согласуются через общие наборы параметров. Плоские криволинейные/вогнутые контуры и отверстия остаются у исходного planar builder.
- Все остальные клетки строятся исходным адаптивным построителем в Float64 на workers: до четырёх для средних задач, до восьми для более тысячи сложных клеток, с учётом `hardwareConcurrency`. После сборки рабочие данные освобождаются. Нормали, adjacency, creases, aliases, picking и отображение строит прежний WebGPU-движок. Старые CPU shading/render mesh и BVH для поверхности не вычисляются. Постоянной CPU-копии треугольной поверхности нет; в RAM остаются управляющий cage и образцы его кривых для выбора контролов. Кэши угловых параметров ограничены.
- Лимит обхода resolver теперь масштабируется с размером cage; при неполном обходе/переполнении числа кандидатов возвращается ошибка вместо публикации неполной поверхности. Для полностью плоского графа используется planar resolver без лишнего пространственного перебора. Геометрически одинаковые кривые, отличающиеся переносом/масштабом, используют общий ограниченный кэш параметров; координаты пересчитываются из своих исходных Float64 controls. Почти одинаковые параметры после объединения сторон удаляются перед проверками нормалей.
- Draw spline: щелчки ставят точки, drag при создании задаёт ручки; щелчок по первой точке замыкает последовательность, ПКМ/Escape заканчивает рисование. Новые сплайны создаются в плоскости последнего активированного действием вида: Top/Perspective — XZ, Front — XY, Right — YZ. В quad view простое наведение на другой вид не меняет активный. Ориентация хранится штатной affine matrix объекта, дополнительных HASH-полей нет.
- Vertex mode показывает только точки и ручки выбранного editable spline/cage; цвет самой кривой остаётся прежним. Параметрические splines не показывают контролы и выбираются как объекты, как и сущности без элементов соответствующего режима Vertex/Edge/Polygon. В Objects Browser editable spline выделен тёплым цветом, параметрические кривые — синим.
- Вершины и концы ручек имеют радиус hover/pick 10 CSS px. Выбранные точки оранжевые, hover светлый; тангенты — тонкие серые линии. Условный масштаб отображения ручек равен 0,5/0,5522847498307936: у окружности R=1000 мм ручка видна длиной 500 мм. Исходные cubic controls остаются неизменными; hit testing, перемещение и масштабирование учитывают этот коэффициент.
- В ортографии ЛКМ выбирает вершины editable spline рамкой, в перспективе — Alt+ЛКМ. Пустой клик снимает и выбор контролов, и выбор владельца сплайна. Ctrl+A во viewport выбирает контролы текущего editable cage. Общая гизма и Coordinate Manager перемещают, вращают и масштабируют выбранные вершины вместе с прикреплёнными ручками. Для одиночной точки/нулевой оси размер для scale берётся из видимых ручек с ненулевым запасным масштабом, без GPU-измерения отсутствующего mesh.
- Контекстное меню Vertex содержит Soft для hard/смешанного выбора либо Hard для полностью soft; Equal Tangents доступен при ненулевых ручках. Команды действуют на звезду выбранной вершины, не обнуляя ручки соседних вершин. Delete из Objects Browser либо при курсоре вне viewport удаляет выбранный spline целиком независимо от режима; во viewport editable controls удаляются как элементы.
- `C` преобразует параметрическую кривую в editable spline. Для объёмного примитива/генератора первый `C` создаёт editable spline patch с исходным cage, второй — обычный polygon mesh. To Spline Patch явно создаёт cage-объект. Матрица и материал сохраняются, при переходе в mesh снимается флаг generated. `F` кадрирует spline-объект. Вычисляемые треугольники генератора не редактируются как исходный mesh; spline patch редактируется через cage. SVG-гизма передаёт контекстное меню canvas своего вида, чтобы доступны были команды текущего сплайна/режима.
- Генератор создаётся над выбранными spline-объектами, которые становятся его детьми. Для Sweep нужны профиль и путь в порядке Objects Browser. Группы внутри генератора обходятся рекурсивно. Входные cages переводятся в локальный frame генератора с полной аффинной матрицей. Изменение параметров/исходного cage/их взаимных трансформов перестраивает результат; устаревшая сборка не публикуется. Ошибки параметров показываются в Attributes; Save ждёт актуальную сборку и не записывает устаревшую поверхность при ошибке.
- Objects Library: работают Square, Circle, Polyhedron, Text, Helix, Gear, Pulley, Cube, Cylinder, Tube, Sphere, Capsule, Nut, Washer и Bolt. Крепёж использует исходные размерные таблицы и варианты старой версии, включая T-slot/rivet nuts, toothed/split washers и восемь типов винтов/болтов; размеры и длины зависят от выбранного типа. Car, Tree и Human загружают исходные модели Frame r248 из локального каталога `models/`; доступны все позы людей, два уровня детализации четырёх деревьев/кустов и цвета автомобиля. Текст использует встроенные сжатые данные Droid Sans, распаковываемые при первом Text.
- HASH: один новый адрес свойства `spline` = `60ff567f12db4fbea03cf36d8170f725`. Низкий TYPE остаётся **0 (bytes)**. Payload **SLP1** имеет фиксированный бинарный layout: subtype, именованные типизированные параметры, наличие cage, версия/счётчик, вершины и ручки Float64, локальные строковые ID, индексы концов/последовательностей, флаги и свободные ручки. Основной spline cage остаётся типизированным бинарным payload. С появлением Morph/анимации существующий адрес `parameters` с TYPE text хранит версионированные authoring metadata; это не вычисленная геометрия. Проверяются длины, конечность чисел, уникальность ID и владение/связность последовательностей. Новых kind объекта нет: чистый spline — group с этим свойством, объёмный параметрический объект — mesh-владелец с тем же свойством.
- Сохраняются **исходные параметры и авторский cage**, а вычисляемые positions/indices генератора или примитива пропускаются. При Open они заново строятся из канонических данных; обычные polygon mesh сохраняют прежние GPU arrays. Матрицы, иерархия и общие material tags продолжают использовать существующие записи. GPU descriptors вычисляемой поверхности — только runtime cache. После `C` mesh становится самостоятельным canonical mesh и сохраняет свои positions/indices.
- Spline undo использует общую хронологию UI/GPU. UI snapshots ограничены 64 MiB (консервативно по UTF-16 строкам) и учитываются внутри общего RAM-бюджета 256 MiB вместе с GPU-offload/redo/reservation. При drag обновляются только затронутые sampled-кривые и GPU-диапазоны controls; события coalesce через requestAnimationFrame. Полная поверхность пересобирается после завершения жеста. Перенос всего генератора сохраняет surface buffers; зависимость определяется локальными матрицами входов, а не world matrix. Рабочие массивы последней сборки не удерживаются сериализующей Promise-очередью.
- Проверки во встроенном браузере: все 15 библиотечных типов, варианты крепежа, Extrude/Lathe/Sweep/fillet, отверстия и 2/3/4/5-sided клетки, бинарный HASH round trip, отсутствие открытых швов у замкнутых примитивов, соответствие GPU-позиций исходному Float64 ядру. Проверены выбор точки мышью, прямой drag, перенос гизмой, Undo/Redo и числовая правка. Harness и JSON результатов находятся в текущем workspace `work/`.

## Материалы, мэппинг и освещение

- Отсутствие material-тега означает Default: sRGB-серый 0,5, roughness 0,5, metalness/emission 0, opacity 1. Быстрый indexed shader использует те же значения, что явно назначенный Default; прежний синий fallback удалён. Default неизменяем: его правка создаёт отдельный материал, поэтому дополнительные теги/буферы всем объектам не нужны.
- Штатные softbox SG-lobes направлены по нормализованным векторам `[-0.4, 0.65, 1]` (sharpness 24, energy 1,3) и `[0.7, 0.5, -0.4]` (sharpness 12, energy 0,5). Оба находятся выше горизонта: двухточечный студийный свет. Оба имеют нейтральный белый RGB; hemisphere gradient также серый, без коричневого/синего тинта. Это окружение, не два локальных прямоугольных источника. В шейдере у dielectric (`metalness=0`) F0=0,04 и отражение растёт к силуэту по Schlick Fresnel: чёрный base с roughness=0 может иметь светлый отражённый край при emission=0. Base color не обнуляет specular диэлектрика.

- Material Editor визуально и по набору параметров остаётся прежним. Удалено добавленное поле selection. Цвет/HSL, emission, roughness, metalness, opacity, bump, цветная текстура и opacity map работают в нативном WebGPU, без Three.js. Неокрашенная сцена использует простой indexed pipeline; материал целого объекта также сохраняет indexed draw. Только полигональные назначения, imported UV и Solid+Wire используют corner draw с точным ID треугольника.
- Полигональное выделение принадлежит material-тегу: отдельного S/selection-тега больше нет. В Polygon mode пользователь выделяет полигоны и перетаскивает материал из списка/превью на них во viewport либо на объект в дереве. Без активного полигонального выделения материал назначается всему объекту. Дроп во viewport выполняет GPU ray pick реального объекта (включая Wire и все виды), без изменения выделения; пиксельные перекрытия гизмы не мешают дропу. Дроп на existing material-тег заменяет материал, сохраняя его маску. Маски пересекаются: правый тег побеждает. Контекстное меню material-тега позволяет снова выбрать его полигоны.
- Удаление material-тега удаляет и его маску из активной сцены/сохраняемого HASH. Bitmap может временно оставаться на GPU, пока его требует Undo/Redo; после очистки истории освобождается. Bitmap — один бит на исходный треугольник, без CPU-зеркала. Копия объекта получает независимые masks/UV и новые IDs тегов; библиотека материалов общая. Derived GPU-table содержит базовый материал, ограниченные теги и битовые маски, без uint32 на каждый полигон всей сцены. Поиск ограниченных тегов идёт справа налево. Добавленные топологией полигоны не входят автоматически в старые маски.
- Наследование: ближайший предок с материалами задаёт материал всем потомкам без собственных material-тегов. Наличие хотя бы одного собственного material-тега полностью исключает объект из наследования, даже если этот тег действует только на часть полигонов. Непокрытые полигоны такого объекта используют обычную поверхность по умолчанию. Собственные теги дочерней группы аналогично перекрывают материал вышестоящей группы для её ветки.
- У объекта два вида мэппинга. По умолчанию — кубическая проекция: выбирается одна из шести граней по направлению нормали, затем один texture sample, без triplanar-смешивания. Локальный projection cube по умолчанию совпадает с BBox объекта. При необходимости хранится только его локальная affine matrix Float64[12]. Для выбора грани используются нормализованные нормали плоскостей обратной матрицы куба: неравномерный scale растягивает проекцию без случайного переключения граней. Куб следует за объектом и деревом; сама геометрия и текстуры при его трансформации не переписываются.
- UV Edit на панели включает нашу общую гизму «3 в 1» для куба проекции. Пунктирный куб показывается во всех видах; move/rotate/scale, skew через Alt+scale, квантование, global/object coordinates и Coordinate Manager используют существующую математику. Меняется только проекция, есть Undo/Redo и отмена жеста. Imported UV-tag переводит объект на импортированные координаты; куб в этом случае не редактируется. Редактора развёрток/unwrap сейчас нет.
- Imported UV представлены единственным UV-тегом меша: два Float32 на угол треугольника, поэтому швы не требуют дублировать logical vertices. В RAM — GPU-дескриптор, данные на GPU. OBJ импортируется как один mesh, исходные координаты трактуются как мм, vt автоматически создают UV-тег; отрицательные индексы и concave polygons поддержаны, n-gons триангулируются ear clipping. Parser Worker создаётся только при открытии OBJ. STL не содержит UV, сохраняет кубическую проекцию и прежний 64-copy нагрузочный импорт. При добавлении геометрии новые imported UV-corners инициализируются (0,0); исходные координаты сохраняются, при Undo/Redo размер буфера следует за количеством полигонов.
- Цветные картинки и opacity map по-прежнему используют общий RGBA8 texture array с максимальной стороной 1024 для viewport. Исходные PNG/JPEG/etc сохраняются в HASH без уменьшения разрешения. Bump получает градиент яркости цветной карты. Прозрачность — weighted blended OIT без сортировки треугольников на CPU: 10 байт на физический пиксель, targets общие между видами и существуют только при необходимости. Это приближённое многослойное смешивание. При прозрачности кэш неподвижного фона трансформации отключается для корректной композиции.
- Освещение — одно процедурное окружение в мировых координатах: вертикальный hemisphere gradient и две spherical Gaussian softboxes. Никаких дополнительных realtime direct lights/GGX-циклов по источникам в material shader. На GPU предварительно строятся diffuse cube 16×16 и prefiltered reflection cube 64×64 с семью mip levels (около 270 КиБ суммарно). На пиксель — два environment samples, Schlick Fresnel полиномом и простые операции diffuse/metalness/emission. Roughness выбирает готовый mip. Карты общие для всей сцены/видов, пересчитываются только при изменении мирового направления, параметров или эффективной видимости источников. Перемещение, масштаб и roll без изменения направления не запускают повторный bake; камера, материал и обычные кадры тоже не запускают его. Compute-предфильтрация — приближённая SG convolution, это не path tracing и не shadow maps.
- Infinite light — полноценный native object kind 2, без mesh-буферов. Кнопка панели создаёт объект у выбранного пивота либо центра камеры, с направлением штатного softbox и angular size 30°; он выбирается в дереве, имеет нашу гизму и направляющую стрелку. Локальная +Z и видимая стрелка задают направление распространения света, а пятно окружения находится с противоположной стороны (−Z). Rotation меняет это направление; position перемещает только его управляющий значок, освещение бесконечно удалено. В Attributes — intensity, temperature K и angular size. Первые два источника по порядку дерева забирают два штатных softbox-пятна, последующие добавляют свои Gaussian lobes в то же окружение. Disable/visibility выключает вклад занятого слота; удаление освобождает слот. Наследуемые матрицы и видимость групп учитываются. Temperature переводится в RGB один раз при пересчёте окружения; 6500 K откалиброваны в нейтральный [1,1,1].
- Все реализованные операции используют общую хронологию Undo/Redo: UI metadata (назначение/удаление материала, параметры/объекты), object transforms, UV projection и GPU geometry edits. Ctrl+Z из viewport/дерева также отменяет назначение материала. UI snapshots содержат только небольшие metadata/affine frames; affine frames исключены из сравнения логических UI-изменений, чтобы трансформ не создавал лишний UI checkpoint. Повторный blur уже закрытого числового поля не открывает новую транзакцию; Undo/Redo и смена выбора очищают временную numeric session. Поэтому Coordinate Manager после Undo показывает восстановленные значения. GPU geometry не копируется ради назначения материала или UV Edit. Новое действие очищает обе ветки Redo. Imported UV и private mask buffers живут столько, сколько они нужны сцене/истории.
- HASH не содержит JSON, новых базовых TYPE нет. `materials`/`assets` — корневые списки ID; `tags` у владельца задаёт порядок. Материал: UTF-8 name, восемь Float64 параметров, необязательные две ссылки maps. Material-тег: ссылка на материал и необязательная собственная bytes-маска `faces` под ID этого же тега; отдельного ID/сущности «селект» в файле нет. UV-тег: собственный Float32 массив `uv`. Меш: необязательная Float64[12] `projection`. Infinite light: object discriminator 2 и Float64[3] `light` (intensity/K/angle), матрица/родитель/флаги общие с другими объектами. Изображение: исходные encoded bytes или относительный UTF-8 путь. Каждый новый property описывает необходимые исходные данные; environment cubes, material tables, viewport texture array, UV-mode, OIT и Undo не сериализуются. Строгий Open проверяет владельцев, ссылки, типы, границы masks/UV и affine matrices до удаления старой GPU-сцены. Миграции старого формата материалов пока не нужны.

## Правила архитектуры

- Чистый WebGPU/WGSL, без Three.js/WebGL. Рендер только по необходимости, постоянного цикла кадров нет.
- После импорта геометрия, топология, нормали и selection хранятся на GPU. В RAM остаются метаданные и ограниченный undo; постоянных CPU-копий геометрии нет.
- Одна логическая вершина — одна позиция. Creases разделяют shading aliases, а не геометрические вершины: перемещение не должно создавать щели. Нормаль упакована oct `snorm16×2`; плотная запись normal + logical vertex ID занимает 8 байт.
- Crease при угле **более 44°**. Нормали STL игнорируются, нормали считаются на GPU.
- Импорт binary STL: CPU-конвертация и точный weld, затем GPU-чистка в пределах **10 ULP float32 по каждой координате**. Представители — реальные исходные точки, без цепочного разрастания допуска. Схлопнувшиеся треугольники удаляются. Отдельный weld при завершении перемещения единственной вершины описан ниже; трансформы целых объектов и наборов вершин не запускают его.
- Lazy-работа примерно через 32 мс простоя, мышь отпущена. Готовый результат публикуется целиком, устаревший отбрасывается; GPU-команды посередине не отменяем. Трансформация целого connected-острова сохраняет углы, пересчёт creases не нужен.
- Undo: один снимок на GPU, в простой офлоад в RAM; строгий бюджет **256 MiB**, включая незавершённый офлоад и redo. Старые записи вытесняются. Слишком большой снимок геометрии остаётся GPU undo; крупная отменённая объектная копия остаётся отделённой от сцены на GPU до Redo или сброса этой ветки истории. SSD не используется. Пустой клик/отмена не добавляет историю.
- Обычный путь — storage buffers. Для сеток сверх лимита одного буфера есть texture-backed GPU-блоки с общей топологией: границы не разрывают connected/сглаживание. Требуются read/write storage textures. Общая VRAM конечна. Есть пулы буферов, BBox/frustum culling и восстановление после device loss.

## Поведение и интерфейс

- Двойной клик и Select Connected в контекстном меню Vertex/Edge/Polygon: GPU ray picking → свежий GPU BFS connected, без кэшированных component IDs. Запрос ждёт завершения первого click-pick и текущей правки, вместо пропуска во время selectionBusy. **Alt+ЛКМ — рамка**, заменяет выделение после отпускания; Escape отменяет рамку. Всё определяется вершинами: один compute-проход по логическим вершинам проверяет проекцию и попадание в рамку. В Solid/Solid+Wire добавляется scene-depth видимость (центральный пиксель, при отказе соседние 2×2 и принадлежность incident face). Это консервативная пиксельная проверка, возле силуэта возможен допуск около пикселя. Wireframe глубину игнорирует. Затем ребро выбирается, если прошли обе вершины, полигон — если все три, даже если его середина видна, а вершина закрыта. Граница рамки включена. Субпиксельные элементы не зависят от наличия raster fragments.
- Маска прошедших вершин — один общий GPU scratch-битсет по самому большому mesh, очищается между mesh. Из него compute восстанавливает выбранные элементы и отдельную маску редактируемых вершин; прошедшие вершины без выбранных рёбер/полигонов в transform mask не попадают. Счётчики редуцируются по workgroup. Отсекаются BBox вне рамки; пока тянешь — только DOM-рамка. `canvas.dataset.boxSelection.phases` содержит GPU-время проверки вершин/восстановления элементов, wall-время BBox/последнего кадра и GPU-время полного кадра, если timestamp готов. Total теперь включает ожидание последнего GPU-кадра.
- Отдельный GPU-битсет активного типа элементов и прежний битсет логических вершин для редактирования. На CPU читаются только счётчики и BBox, не геометрия/selection. Выбранные элементы рисуются оранжевым отдельным проходом, hover cyan. При смене Vertex/Edge/Polygon рамочное выделение сбрасывается; при смене shading сохраняется. Рёбра сохраняют ID после ленивого пересчёта creases. Одиночный клик выбирает один элемент через существующую GPU-ID карту (Vertex/Edge — тот же поиск в радиусе 10 CSS px), маски не читаются на CPU; появляется мини-гизма. Двойной клик по-прежнему connected. Выбранные вершины — круглые маркеры диаметром 9 CSS px, включая connected в Vertex.
- Hover полностью на GPU, без readback: Polygon — треугольник под курсором; Vertex/Edge — ближайшая логическая вершина/уникальное ребро в радиусе **10 CSS px**. Solid/Solid+Wire допускают только видимые фрагменты, Wireframe — все. Тонкая `R32Uint` карта ID + depth, 128 потоков ищут победителя в круге; при совпадении пикселя выигрывает ближайший к камере. Это пиксельная точность. Подсветка cyan: одна точка 3 px или видимая часть ребра. Shading aliases не создают дубликатов вершин.
- Цвет и ID поверхностей кэшируются (8 байт/физический пиксель); карта элементов с depth лениво добавляет ещё 8 байт/пиксель. При движении мыши — маленький compute + экранный проход, без перерисовки сетки; карты обновляются при смене вида/геометрии/режима. Цвет рисуется без ID на всех GPU. ID поверхности — отдельный проход после idle/явного запроса. `primitive-index` используется только для индексной карты рёбер; fallback карты — неиндексные линии. В Wireframe ID поверхности нужен только для Polygon. Смена выделения переиспользует hover-карту; ключ включает вид, режимы, размеры и версии геометрии. Hover скрыт во время жестов; карты в это время не строятся, один раз обновляются после отпускания мыши. Построение карт требует прохода по геометрии и на 100 млн треугольников заметно удорожает кадр при движении камеры; cached hover от размера сетки не зависит.
- Исходная Frame SVG-гизма «3 в 1»: полосы move/scale, площадки плоскостей и четверть-дуги rotation, Alt+осевой scale — skew. См. контракт трансформов выше. Несколько выбранных моделей получают одну матрицу на GPU и один общий undo (снимки каждого затронутого mesh). Полные снимки больших selection требуют дополнительной VRAM; компактный undo выбранных позиций пока не реализован. Частичное рамочное редактирование ставит creases в lazy-очередь. Ctrl+Z / Ctrl+Я — undo (физическая KeyZ и обе раскладки), Escape — отмена. Undo после окончания жеста также ставится в очередь, если GPU ещё завершает транзакцию.
- Модификатор фиксируется при нажатии на область гизмы. **Ctrl+transform** копирует только полностью выбранные треугольники: в Vertex нужны все 3 вершины, в Edge все 3 ребра; иначе копию и трансформацию не делает. Свободных вершин/рёбер не создаёт. **Shift+transform Polygon** заменяет выбранную крышку её копией и строит по 2 треугольника на каждом ребре периметра; внутренние рёбра стенок не дают. **Shift+transform Edge** достраивает по 2 треугольника между выбранным ребром и новыми концами. Shift в Vertex — обычная трансформация; Ctrl имеет приоритет.
- Topology edits строят новые canonical positions/indices и плотные карты вершин на GPU; readback только небольших счётчиков. Новая геометрия публикуется целиком после успешной сборки. Используется paged backend, import-cleanup намеренно пропускается: совпадающие при старте копии не должны свариваться. Сохраняется identity mesh-объекта, переиндексируются глобальные IDs. Undo топологии хранит старые позиции/индексы, маску вершин, порядок рёбер и exact element bits, затем восстанавливает backend исходного типа; обычные более ранние undo остаются валидными. На время жеста есть временный GPU source для матрицы, после отпускания освобождается. Creases после partial edit — прежняя lazy-очередь. Сейчас перестраивается весь затронутый mesh: это простой первый вариант, не локальная инкрементальная топология.
- Solid / Wireframe / Solid + Wire. Wire чёрный, около 1 физического px. Чистый Wireframe теперь вычисляет покрытие всех уникальных рёбер в compute: один поток на ребро, homogeneous clipping, экранный проход по главной оси и diamond-exit с фиксированной субпиксельной точностью. Атомарная маска пикселей объединяет повторные попадания; отдельный полноэкранный проход наносит чёрный wire поверх сетки, без отбрасывания задних рёбер. Нет LOD, геометрической фильтрации или CPU-копии. Нативный line-list остаётся до готовности лениво компилируемого compute pipeline. Маска общая для видов, 4 байта на физический пиксель (около 1,9 МиБ при 841×589); при resize переиспользуется/заменяется, при выходе из Wireframe освобождается. Поддерживаются storage-buffer и texture-backed positions, world-матрицы, подбор объектов/элементов и кэш неподвижной части трансформации. FPS включает compute, очистку маски и её вывод, а не только последний экранный проход.
- Solid+Wire по-прежнему использует barycentric shader и неиндексный draw углов треугольников на всех GPU. Внутренние углы видны. Все вершины постоянно не рисуем: только выбранные и одну при hover.
- Y вверх; импорт `(x,y,z) → (x,z,-y)`. LMB orbit вокруг поверхности под курсором, MMB pan, колесо/RMB zoom к курсору в world space. RMB вверх-вправо приближает. Обычный курсор-стрелка. Zoom без искусственного лимита, без изменения FOV 45°/поворота. Far clip по BBox, near = far/10000.
- Canvas занимает перспективный вид рядом с правым интерфейсом. Английский UI, monospace 14 px, тёмно-серые панели. Внутри видов — условный FPS = 1000 / GPU-время кадра и HUD памяти. Triangles доступны в диагностике. Это не частота показа; энергосбережение GPU влияет на замеры.
- HUD: `VRAM: 92.3%` (только процент; подробности остаются в tooltip). Системные used/free берутся у драйвера, включают остальные программы; знаменатель процента = used+free, без зарезервированной драйвером части установленной памяти. Tooltip различает установленный объём, доступный физический объём и приблизительные ресурсы приложения; это не измерение резидентности ресурсов и не бюджет конкретного процесса браузера. WebGPU сам не раскрывает свободную память ([GPUWeb #5505](https://github.com/gpuweb/gpuweb/issues/5505)), поэтому локальный `serve.py` предоставляет необязательный read-only endpoint `/__frame/gpu-memory`, использующий уже установленный `nvidia-smi`. Опрос раз в 2 с, без параллельных запросов к драйверу на сервере; на скрытой странице приостанавливается. Если невозможно однозначно сопоставить адаптер/драйвер, endpoint недоступен или показание устарело — `—%`, без догадок по названию карты/лимиту буфера. Дополнительных JS-файлов приложения нет; диагностика памяти не сериализуется в HASH.

## Живая spline patch, виды и Share — 18.10.2026

- Навигация средней/правой кнопками, wheel и double-click проходят через гизму в соответствующий viewport. ЛКМ сохраняет обычные трансформы. При входе в Vertex/Edge компонентные masks очищаются: целый polygon mesh не окрашивается жёлтым; явно выбранные компоненты остаются обычным выделением.
- Shading хранится отдельно для каждого вида. Кнопка меняет активный вид; переключение вида обновляет её состояние. Defaults: перспектива **Solid+Isoparms**, три ортографии **Isoparms**. Четыре режима сериализуются существующей записью камеры HASH, без нового TYPE. Старые camera records получают новые defaults.
- У authored `spline_patch` есть **angle approximation**. Первый To Editable сохраняет точность исходного параметрического объекта; legacy patch наследует angle из cage. Изменение параметра синхронизирует общий угол и override сегментов и перестраивает поверхность. Второй To Editable по-прежнему создаёт polygon mesh.
- Во время drag вершины/тангента или трансформа выделенных spline controls cage перерисовывается сразу, а surface builder работает асинхронно в workers ещё до отпускания мыши. Одновременно выполняется одна сборка; новые изменения объединяются в самое свежее состояние. Во время активного жеста допускается публикация завершённого промежуточного снимка; после release обязательно публикуется точная последняя версия. Проверяются владелец сцены, тип, существование объекта и актуальность результата. Undo — одна операция на жест; Cancel/Undo не принимают устаревшую поверхность.
- У worker есть ограниченный кэш результатов отдельных произвольных ячеек: бюджет до 4 MiB на lane (до 32 MiB на восемь), учитывающий typed arrays, ключ и оценку boundary metadata. Ключ включает fill, геометрию границ, sampling parameters и approximation. Повторяющаяся форма ячеек не требуется: повторно используются **неизменившиеся** ячейки того же cage. Resolver и общие sampling cuts пересчитываются; изменения планарности/заливки входят в ключ. Главный поток не хранит зеркало поверхности. GPU fast path регулярных patch сохраняется; general Float64 builder работает в workers. Вспомогательные lanes семплируют только границы назначенных им ячеек.

## Инкрементальные ячейки, дочерний cage, свет и STL — 18.10.2026

- Первый **To Editable** объёмного параметрического объекта создаёт `spline_patch` с дочерним editable `spline`. Родитель хранит генератор поверхности, ребёнок — исходный cage и **angle approximation**. У родителя approximation больше нет. Существующие HASH с embedded cage переводятся в ту же структуру при открытии; исходный fixture не переписывается. Второй To Editable сохраняет поверхность как polygon mesh и удаляет исходных детей в одной Undo-операции. Кривые преобразуются в обычный editable spline. Матричные системы координат родителя/ребёнка сохраняются; при identity frame передача cage не делает ненужную копию.
- При редактировании геометрии остаются стабильными ID resolved cells и индекс segment → incident cells. Проверка новых положений/тангентов определяет только изменившиеся границы. Только связанные с ними ячейки меняют samples/planarity/triangulation. Остальные Float64 результаты остаются в ограниченном worker-кэше. Resolver запускается заново при изменении графа/последовательностей/boundary flags/общего approximation, при первом построении и по явной команде `spline.rebuild`. Геометрическое движение не переизбирает все области заливки каждый кадр. Возврат вершины/тангента точно в исходное положение также пересчитывает только incident cells; для вернувшихся границ восстанавливаются исходные refined sampling parameters, без полного resolver/reset. Для сложных planar contours прежние ограничения kernel (combinatorial topology, не external intersection validator) сохраняются.
- Сборка general CPU cells теперь инкрементальна и на **WebGPU**: неизменившиеся диапазоны canonical positions копируются GPU→GPU, их indices перенумеровываются одним общим compute kernel `remap index ranges`; передаются только новые координаты и indices затронутых ячеек/изменившихся samples. Shared boundary vertices сохраняются, дыр на швах не добавляется. Полная контрольная сборка и инкрементальный результат сравниваются по SHA-256 positions/indices. Если GPU revision не совпала, был сменён владелец/сцена или используется неподходящий backend, выполняется полная сборка из сохранённых ячеек. Regular translation/ruled cubic cells по-прежнему вычисляются существующим GPU evaluator; Float64 решения общих cells остаются в workers. Derived topology/normals актуализируются на GPU.
- Кэш coordinator worker ограничен оценкой 64 MiB, LRU по владельцам поверхностей; вспомогательные workers держат только текущий batch. Геометрия не дублируется целиком в main-thread scene graph. Публикуется один актуальный snapshot; Undo/Cancel отклоняют запоздавший результат. При Cancel явно инвалидируются source и его генераторы, даже если старый input object менялся in-place.
- В Vertex/Edge surface shader никогда не выводит жёлтую заливку из transform mask вершин. Ctrl+A/Connected создают mode-specific element bitset: в Edge рисуются выбранные рёбра, в Polygon — полигоны. Seed Vertex/Edge берётся из того же GPU feature picking footprint, что и одиночный click/hover, включая край за силуэтом. В Polygon используется ray face picking. Счётчик Connected сообщает количество выбранных элементов текущего режима; число пройденных вершин отдельно в `vertices`.
- Select Connected по double-click принимает два primary pointerdown с интервалом **≤300 мс**, расстоянием **≤8 CSS px** в одном виде, и свежий dblclick. Это общее правило для canvas и событий, проходящих через гизму. Контекстная команда Select Connected временным порогом не ограничена. Scroll zoom ускорен: коэффициент .0015 для перспективы, .004 для ортографии.
- Студийный свет стал контрастнее: нейтральные key/fill энергии **1.6 / .22**, оба выше горизонта. Key направлен из [-1,.8,.1], заметно сбоку от стартовой камеры, вместо прежнего почти headlight-направления. Ambient hemisphere уменьшен до .025–.14, diffuse wrap заменён обычным положительным cosine. Это создаёт направленный светотеневой объём, без коричневого tint. Environment по-прежнему запекается только при изменении освещения; стоимость shading на каждый пиксель не увеличена.
- Для уменьшения первого стоп-кадра трансформа posed pipeline variants и shader восстановления статического фона начинают компилироваться асинхронно при выборе объекта, до первого движения. В `test:all` измеряются три первых реальных drag выбранного объекта в сцене `stress-mesh-100m.hash`. Универсальное устранение всех driver/OS pauses не заявляется.
- STL и OBJ используют общий короткоживущий parser worker с transferable ArrayBuffer. STL сохраняет исходные числовые размеры (с прежним переводом осей Z-up → Y-up), создаёт один mesh без искусственного Scene-root; stress-only клонирование удалено из runtime. Камера маленького STL не приближает его автоматически до полного viewport: сохраняется масштаб стартового workspace 100 мм, F позволяет приблизить явно. Масштаб/точные координаты геометрии при этом не меняются; настройка камеры сохраняется в HASH.
- Большой HASH переименован **`frame-before-object-mode.hash` → `tests/scenes/stress-mesh-100m.hash`**, файл 662855464 байта не перекодирован. `test.stl` остаётся пользовательским исходником с неверным масштабом и больше не играет роль 100M-треугольной матрицы.
- AI API **1.1.0**, 24 команды: добавлен `spline.rebuild` — свежий resolver/build без изменения source/Undo; `diagnostics.mesh.cells` — SHA-256 координат внутренних вершин выбранных general cells; `scene.inspect.lighting` — реальные studio lobes/ambient. Описания объектов возвращают `sources`; `spline.inspect`/`replace`/`tangents` принимают patch ID как alias единственного editable source spline. Для нескольких inputs inspect возвращает объединённый cage, а изменяющие команды требуют явный source ID, без молчаливой правки первого ребёнка. `spline.inspect` сообщает `owner` и реальный source `id`, surface report относится к владельцу. `scene.update` approximation адресуется source, не родителю. MCP получает те же схемы автоматически.
- WASM SIMD исследован отдельным универсальным прототипом affine kernels для packed Float32/Float64. На 500000 scalars: JS ~0.50/1.22 мс, SIMD compute ~0.064/0.284 мс, с копированием input/output ~0.334/0.724 мс (Node 24, конкретный CPU). Это экономит меньше миллисекунды, тогда как прежняя задержка определялась глобальным resolver/сборкой и повторными передачами. В runtime WASM не добавлялся: STL больше не делает искусственный affine scale, а копирование/перенумерация geometry уже на WebGPU. Прототип и результаты находятся в `work/wasm-probe` текущего workspace, не являются зависимостью приложения. Float32 SIMD-прототип отличается от JS double intermediates на части входов (максимум ~7.63e−6); Float64 дал идентичные результаты. Это дополнительная причина не подменять им геометрические kernels без проверки точности. [WGSL concrete numeric types](https://www.w3.org/TR/WGSL/#scalar-types) используют f32/f16, а [WASM SIMD](https://github.com/WebAssembly/simd/blob/main/proposals/simd/SIMD.md) предоставляет в том числе f64x2; перенос Float64 решений cells в GPU f32 без проверенного алгоритма точности не выполнялся.

## Boolean, Outline, распознавание и realtime — 18.10.2026

- Перенесены алгоритмы Frame r248 (`editor.14694d2e39a34bf370f7.js`, `boolean-worker.4f0836a2599f29210b37.js`) в ленивые текстовые блоки `index.html`. Исполняемый runtime по-прежнему находится только в этом HTML; workers создаются из Blob, внешних JS/WASM-запросов нет. Подготовка операций не меняет сцену до получения результата; публикация проверяет владельца и ревизию. UI, API и MCP используют одни объекты и историю.
- **Boolean** — генератор над двумя включёнными дочерними операндами: Subtract, Intersect, Union. Работает с polygon meshes/параметрическими поверхностями и замкнутыми плоскими cubic splines. Группы собираются в локальной системе Boolean. Сохранены проверка топологии, копланарные случаи, кубические границы planar Boolean, материалы исходных граней, clipped source cage и линии пересечения. Вычисляемые masks материалов — GPU-кэш результата; при To Editable они становятся обычными material-тегами. Пересекающиеся поверхности рассчитываются исходным Float64-worker: один WebGPU f32-проход не заменяет точные решения топологии. Для разнесённых polygon/surface meshes без material masks, buffer storage и точного целочисленного переноса union/difference собираются WebGPU compute без readback; intersection сразу пуст. Прочие случаи проходят штатный worker. Результаты отражаются в `evaluation.report`, включая backend и материалы. Polygon Boolean → To Editable сохраняет mesh; curve Boolean → editable spline. Source meshes скрываются, пока их потребляет генератор.
- **Outline…** доступен в контекстном меню editable spline/cage. Вводится расстояние в миллиметрах; при наличии выделенных сегментов используются они, иначе весь исходный spline. Перенесены исходные planar/3D kernels, обработка пересечений и кубическая реконструкция. Замкнутый контур сохраняется и получает offset-контур; открытые цепочки используют исходное поведение построения полосы. Операция выполняется в короткоживущем Float64-worker и записывает одну Undo-транзакцию. Extrude fillets и Sweep продолжают использовать тот же исходный алгоритмический набор; GPU строит поверхности и их derived данные.
- **To Spline Patch** теперь работает для импортированных polygon meshes: исходный recognizer выделяет плоскости, цилиндры, конусы, сферы и линейные остатки и создаёт управляющий spline. Изменяется topology/logical IDs, поэтому новая поверхность получает новый native hash при сохранении UI id, имени, affine frame и материалов целого объекта. Прежний GPU mesh остаётся в существующем владельце скрытой геометрии для точного Undo; CPU-копия не сохраняется. Imported UV и маски старых полигонов не переносятся на другую топологию. Точность распознавания произвольных промышленных моделей требует проверки на конкретных файлах; тестируются плоская поверхность и замкнутый куб.
- **Realtime render** подключён к Camera (`Render` на панели либо `scene.create: render`). Render запускает progressive WebGPU path tracing перспективы; `realtime=on` обновляет изображение после изменения сцены/камеры и уточняет его после жеста. При движении используется ограниченный preview, после него — выбранные samples. Навигация переиспользует BVH; изменение геометрии/материалов обновляет snapshot. Используется GPUDevice viewport, без Three.js и второго устройства. Перенесены трассировка, GI, importance sampling, reconstruction/denoise, exposure и presentation. Это не обещание 60 FPS для тяжёлой сцены: подготовка BVH и разрешение ограничены устройством и временем расчёта. Большие scenes могут превысить предел одного trace buffer; ошибка отображается в статусе Camera/API. Default environment использует те же три SG-lobes, что viewport; Off/Image сохраняют отдельные authored infinite lights. Для Image нужен `environment image` URL. Image mode допускает до 16 direct infinite lights, как исходный integrator.
- **Infinite light:** helper виден без выделения во всех открытых видах. Красный квадрат (`visible=false`) скрывает helper, сохраняя освещение и не запуская новый environment bake; зелёный (`enabled=false`) выключает освещение, сохраняя helper. Эти два признака наследуются раздельно. Helper не является mesh и отображается поверх realtime preview.
- **Студия:** три нейтральных SG-softbox, все выше горизонта. Sharpness 56/36/64, energy 0.58/0.065/0.09; key direction `normalize([-1,.8,.1])`, fill `normalize([.7,.5,-.4])`, rim `normalize([.1,.7,1])`. По сравнению с прежним светом пятна меньше, peak отражения ключевого источника ниже и contrast мягче. Диэлектрический F0 остаётся 0.04; grazing response rough-материалов использует integrated BRDF approximation. Diffuse cube увеличен до 32², reflection cube — до 256²/9 mip levels, добавлен стабильный dither ±0.5 LSB. Это примерно 4 MiB environment textures вместо прежних 270 KiB, без дополнительных geometry passes.
- **Память spline patch:** канонические позиции/индексы и derived render buffers — GPU. Удалены также массивы positions/indices из worker-кэша построенных CPU cells: остаются counts, boundary IDs, source controls и samples. Неизменённые ячейки копируются/перенумеровываются GPU; при утрате token или сборке, требующей полного CPU результата, ячейки строятся заново. `cpuTriangleCacheBytes=0` в отчёте сборки. Editable cage, samples/picking и небольшие display arrays остаются в RAM намеренно; это не треугольная поверхность. Path tracer временно декодирует render snapshot и сохраняет BVH/refit metadata, но освобождает CPU triangle staging после upload.
- **WASM SIMD:** freestanding kernel встроен в HTML, компилируется только по потребности в workers. Binary STL читает блоки по 32768 треугольников, SIMD выполняет перестановку/проверку Float32 bits, затем точный weld в WASM hash table с ростом; normals/cleanup по-прежнему WebGPU. Для небольшого файла, отсутствующего SIMD или превышенного arena budget сохраняется JS. Float64x2 affine kernel применяется пакетно к крупным render/Boolean operands, с небольшим переиспользуемым scratch. Double intermediates сохраняются, FMA/квантизации нет. Исходник и воспроизводимая сборка — `tools/stl-simd.c`, `tools/build-simd.mjs` (`CLANG` может указывать wasm-capable clang).
- **API v1.1, дополнения:** `spline.outline`, `mesh.toSplinePatch`, `render.start/stop/inspect/pixels`, `material.create/assign`. `scene.create` поддерживает Boolean и Camera; `scene.convert` поддерживает импортированный mesh и обе разновидности Boolean. `diagnostics.mesh geometry:true` дополнительно возвращает signed tetrahedral volume (сам по себе не доказывает замкнутость). `diagnostics.pixels` дожидается текущей компиляции material pipelines, а не читает временный серый fallback. Все команды имеют схемы; ошибки возвращают code. Настройки Camera сериализуются существующим spline parameter codec; новых HASH TYPE не добавлено.
- **Проверки:** новые общие случаи находятся в `tests/features-suite.js`; `tests/simd.mjs` проверяет exact bits, рост STL-таблицы, NaN/Inf и Float64 SIMD. Syntax runner теперь проверяет также пять ленивых программ. ## Копирование, Morph, анимация и общая геометрия — 18.10.2026

- Все новые объекты добавляются сверху Objects Browser; HASH Open сохраняет этот порядок. Object selection дожидается актуальной очереди, поэтому новый выбранный объект показывает штатную гизму. Независимые Ctrl+D, Ctrl+drag, копирование в дереве и Ctrl+C/V идут через native object-copy transactions. Clipboard владеет копией только canonical positions/indices на GPU и compact authoring metadata; последующая правка исходника не меняет вставляемую форму. Spline cages/isoparms восстанавливаются для независимых копий. Clipboard заменяется при следующем Copy.
- Solid + Isoparms рисует polygon edges с depth test и малым clip-space bias; задние рёбра закрыты непрозрачной поверхностью. Spline surfaces и их replicas показывают исходные кривые cage. Короткий click выбирает объект, drag по нему навигирует (orbit в перспективе, pan в 2D); рамки и прямое редактирование компонентов сохранены. При Draw spline гизма временно скрыта, первая точка рисуется в активной плоскости, видны свободные тангенты ещё до первого сегмента. Выход из рисования возвращает прежний режим.
- Модель из предоставленной ссылки (269 vertices / 534 triangles) больше не запускает комбинаторный поиск всех циклов. Нераспознанные области получают авторские cell boundaries. SLP cage version 4 сохраняет edge references, направление и несколько loops на cell, включая отверстия и двухсторонние cubic cells; version 3 с vertex cycles читается. После разделения ребра новые boundary segments подхватываются, при удалении границы соответствующая cell открывается. Вычисленные позиции и индексы не добавляются в authoring data.
- HASH опускает параметры, равные фактическим defaults create(), включая Matrix Cloner / Tangent Sweep, и identity object matrices. Явный pivot не опускается: он может отличаться от автоматического BBox pivot. Camera и не-дефолтные единицы сохраняются. Исходная ссылка: 5251 символ, 3907 bytes gzip, 4038 bytes HASH; indices 1754 и positions 1662 bytes занимают основную часть. Большая часть этого payload — геометрия, а не настройки.
- Instance хранит стабильную ссылку на source hash. Cloner и Symmetry используют дочерние источники и derived draw owners с общими positions, indices, topology, normals и линиями. Отдельные ресурсы — frames, selection bitsets, draw IDs и bindings. Source publication обновляет replicas; lease-счётчики откладывают освобождение ещё используемых GPU resources. Материалы и UV наследуются от источника, material tag генератора может их переопределить. В HASH сохраняются source + параметры, derived geometry отсутствует. Компоненты редактируются у исходника; независимую геометрию даёт обычное копирование исходника. Это sharing buffers; число draw submissions всё ещё зависит от числа replicas.
- Cloner поддерживает Matrix, Radial, Object, seed/random PSR. На spline Object используются Step/Offset, длина sampled cubic path и Parallel/Tangent. На surface Object заданное Count распределяется воспроизводимо по площади треугольников на geometry worker; CPU triangle staging освобождается, кэшируются только placement frames. Это area-stratified sampling, не blue-noise/best-candidate из старого редактора. Лимит — 100000 derived copies на сцену. У выключенного Cloner/Symmetry виден исходник; при ошибке источники не поглощаются. Pure spline replicas делят GPU line buffers. Diagnostics различают active independentPositions и residentPositions/historyMeshes, удерживаемые для Undo.
- Target — marker с полем object. Связанный объект направляет локальную ось +X пивота на Target, с world-up roll correction и сохранением authored affine stretch/pivot position. Ограничение вычисляется из authored frame; отключение Target возвращает базовую ориентацию. Граф parent/target проверяется на циклы. Constraint работает при трансформах и анимации, ссылка сохраняется как hash.
- Анимация использует существующие timeline, XYZ curve editor, tangent handles, key interpolation и Undo. PSR читает/пишет реальные local affine frames, numeric object/material/tag параметры используют те же tracks. Point animation: spline vertices/handles и polygon vertices имеют XYZ tracks; polygon readback собирает только выбранные координаты, запись и пересчёт normals/bounds идут через GPU, включая texture-backed storage. GPU work сериализовано перед Save/следующей API-командой. Tracks и scene frame/total сохраняются; global material tracks также переживают Open.
- Morph Tag имеет Modelling (reference), Edit (pose keys на отдельной шкале 0–100 и XYZ curves), Solve (weights, включая промежуточные нелинейные pose keys и обратный подбор weights по перемещённым контролам). Для z=40, m=2: делительный Ø80, наружный Ø84, впадин Ø75 мм; толщина зуба на делительной окружности π мм (ошибка кубического приближения в проверке <0,000001 мм). Исправлена впадина для z=60, m=2: Ø115 мм вместо провала к базовой окружности. Физический профиль инструмента и подрезание малозубых колёс не моделируются.
- Save As предлагает HASH и STL. STL — binary, миллиметры, видимые вычисленные поверхности, включая матрицы, иерархию и replicas; скрытые/поглощённые генераторами операнды и одни кривые не экспортируются. Обратная перестановка осей соответствует STL import, normals считаются по конечным вершинам, отражённые матрицы меняют winding. Запись по 4096 треугольников; GPU readback временный, по одному mesh. HASH по умолчанию сохраняет весь авторинг. `scene.export` получил необязательный `format: hash|stl`, default hash.
- Двойной клик по пустому месту Materials создаёт материал; по любой части карточки открывает Material Editor. Pointer capture остаётся на карточке, чтобы click/dblclick не перенаправлялся на пустую библиотеку. Клик по объекту выбирает его материал (или унаследованный материал группы) в редакторе.
- Окружение согласует интегральную энергию diffuse/specular: diffuse нормирован по π, энергия софтбоксов пересчитана с сохранением общей diffuse-яркости. Roughness 50 сохраняет широкие отражения, Roughness 100 сильнее размывает их. Проверки отражений используют существующий `diagnostics.pixels` без дополнительного renderer или дублирующей API-команды.
- Solo на 1000 объектах больше не запускает декодирование всех authoring records при каждом кадре камеры. Запись камеры не инвалидирует object cache, HASH-address cache вмещает рабочий набор большой сцены. CPU timing включает overlays/gizmo. Материальная библиотека вычисляет используемые assets один раз на изменение сцены/материалов, а не для каждого mesh; иерархия имеет производный индекс детей. Пустой `FrameSpline.flush` не переписывает сцену; UI copy сериализован и учитывается `frameAI` settle. Изменение параметров Render явно планирует preview.
- Morph повторяет исходные состояния: кнопки Solve / Modelling / Edit; Modelling скрывает poses; Solve меняет веса и не показывает Add/Capture; Edit даёт Add Morph, переименование двойным кликом по имени, отдельное время 0..100 со стартом 50, числовое поле перемещает время активной позы. Spline patch редактирует свой source child, сохраняя Attributes владельца тега. Служебные перестроения сохраняют выбор тега и не запускают вспышку BBox. Sparse vertex/segment/free-handle дельты и pose XYZ curves сохраняются в прежнем native authoring codec; polygon reference остаётся на GPU.
- `tests/followup.mjs` проверяет реальные жесты гизмы, кольца/подсказки/snapping, СКМ, pen/free tangents, dblclick Materials, материал объекта, отражения при roughness 50/100, binary STL round trip, Morph UI и Solo 1000 объектов. `release.mjs` дополнительно повторяет все три Boolean на исходной STL после 1000× Rescale и последовательного переподчинения операндов.
- Тяжёлые `test.stl`, `stress-mesh-100m.hash`, `release-1000-10m.hash` остаются локальными и исключены из Git. Малые fixtures, Khronos helmet и генератор нагрузочной сцены публикуются.

- Копирование полигонального Morph и clipboard сохраняют отдельную исходную форму на GPU: дельты не применяются повторно к уже деформированным вершинам. Архив Copy Undo хранит rest positions; Redo и HASH восстанавливают тот же pose. Проверяется изменение исходного веса после Copy, независимая вставка, Redo и HASH при ненулевых весах. Morph Edit блокирует изменение длины временной шкалы и возвращает прежнее состояние при выходе. Быстрое переключение Realtime учитывает изменение Camera options синхронно, без зависимости от 32 ms preview-таймера.
