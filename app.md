# Frame application context

Frame is a 3D editor for large triangle meshes and spline patch models. The core runtime is `C:/frame/index.html`: UI, native WebGPU renderer, WGSL, workers, embedded geometry kernels and HASH codec. Optional plugins live independently in `plugins/`; their contract is documented in `plugins.md`. `app.md` describes the application; `AGENTS.md` defines development requirements. Priorities are large-scene speed, bounded memory, compact native files and simple code. Polygon n-gons are triangulated; a separate n-gon editing model is not planned.

Keep code, documentation, fixtures and UI text in English. Conversation may be Russian or English. Change the application interface only when the user asks for that change. Preserve the established layout, icons and gestures outside the requested scope. Attributes must contain only actual editable parameters and their labels or controls. Never add explanatory prose, instructions, placeholders, logs, progress reports, warnings or error messages to Attributes for any object, tag or tool. Failed or inapplicable operations quietly leave the scene unchanged; never display operation errors anywhere in the interface. Keep diagnostics in the automation API or nonvisual developer data only. This rule has no exceptions for convenience or debugging. The user prefers action without unnecessary confirmations and does not want screenshots posted in chat.

The printer Slice action is the one authorized exception for extremely short progress immediately to its left. Slice builds persistent orthogonal X/Z GPU LDIs for all layers; Finish layer reconstructs a white/transparent coverage map without rebuilding them. Perimeters and toolpaths remain deferred. See plugins/3d-printer/AGENTS.md and plugins.md for supported geometry and explicit limits.

The AI developer owns automation and diagnostics. When a task exposes missing or inconvenient automation, improve `window.frameAI`, its schemas, documentation and regression coverage in the same task. MCP is a thin transport to that API. Reuse editor transactions, authored cages and native GPU resource ownership; never introduce a parallel AI scene graph or geometry engine. Compatibility with earlier formats, APIs or behavior is not required until the user explicitly requests it. Do not add speculative migrations or compatibility layers.

## Runtime, storage and ownership

- Use native WebGPU/WGSL. Three.js, WebGL, GLTFLoader, CDN scripts and external JavaScript runtime dependencies are absent. The application renders on demand, without a permanent animation loop. Development launchers, tests and model/texture assets may be separate files.
- Canonical polygon positions, indices, topology, normals, selection and editing resources live on the GPU. RAM holds authoring metadata, spline controls/samples and bounded history. Temporary import/export, geometry algorithms and explicit diagnostics may read geometry; they must not leave a permanent CPU mirror of a polygon surface.
- One logical vertex owns one position. Creases split shading aliases rather than geometric vertices, preventing cracks during movement. Octahedral normals use `snorm16x2`; a packed normal plus logical vertex ID takes eight bytes. The crease threshold is greater than 44 degrees. STL normals are ignored.
- Ordinary meshes use storage buffers. Meshes exceeding a binding limit use texture-backed canonical data and bounded GPU blocks, with shared topology across block boundaries. Connected selection and smoothing must cross those boundaries. Read/write storage textures are required. Resource pools, bounding-box/frustum culling and device-loss handling share the same GPU session.
- Expensive maintenance is deferred until idle, normally about 32 ms after input. Publish a complete result after checking its owner/version; reject stale results. Already submitted GPU commands are not cancelled midway. Rigid movement of an entire connected island preserves crease angles.
- Undo has one GPU snapshot and idle RAM offload. The strict 256 MiB RAM budget includes pending offload, reservations, UI history and Redo. UI snapshots are additionally limited to 64 MiB, estimated conservatively as UTF-16 strings; metadata transform history is bounded to 100 actions. Evict old records. A snapshot too large for RAM stays on the GPU; large undone copies may remain detached until Redo or history retirement. No SSD history. Empty clicks and cancelled unchanged gestures create no history.
- UI metadata, object frames, projection edits and GPU geometry use one chronological Undo/Redo sequence. New edits clear both Redo branches. Imported UVs and private material masks remain alive while scene/history needs them. Material assignment must not copy geometry.

## Views and navigation

Top looks along -Y, with +X right and +Z up. The shared projection, inverse rays, drawing frame and front-face shading parity use this orientation, including plugin overlays. Front looks along -Z, with +X right and +Y up. Right looks along -X, with -Z right and +Y up. Perspective and each orthographic view have independent cameras, shading and projections. Hovering another viewport does not activate it; an action in that view does.

Middle-button pan starts immediately. A short middle click switches single/quad view under the pointer: up to 350 ms and 24 CSS px, or up to 180 ms and 72 CSS px. Restore the pre-pan camera before accepting a click. Longer/farther motion remains Pan. Wheel and right-button zoom anchor to the cursor. Perspective retains orbit navigation; a completed right-button navigation suppresses the context menu until the next pointer press. Physical `KeyboardEvent.code` drives shortcuts in any keyboard layout; text fields retain normal text entry. Arrow transforms require the pointer to be over a viewport and follow the last gizmo operation (Move, Rotate or Scale). Focused numeric fields, enum fields such as Car color, and switches own their arrow keys even while the pointer is over a viewport.

Alt + left drag selects a rectangle in every viewport. In orthographic views, an unmodified left drag moves, rotates or scales the selection according to the last gizmo operation. With no selected object it starts a rectangle. A short click still selects. Curves uses plain left-button marquee in the graph and Alt + left marquee in its bottom timeline strip; middle-button pan remains available. Timeline rectangles select every axis represented by enclosed keys, preserve the view and key values, and use the same key Delete/Undo path. Curves receives its own keyboard events before viewport spline tools. Its vertex context menu exposes Soft, Hard, Equal tangents and Fit. Shift adds, Ctrl/Meta toggles hit components; a rectangle latches its modifier on pointerdown. Browser Shift-click selects the inclusive visible row range from its anchor. Browser Ctrl-click toggles individual rows.

Selection rectangles use a blue `#6394ff` outline with no fill, distinct from spline curves. Escape cancels a rectangle. Object/group selection flashes a yellow bounding box for 350 ms and shows the gizmo without filling millions of vertex-mask bits. Repeated selection restarts the flash in every component mode. Group bounds include pure spline descendants; empty groups use a small screen-space box at their origin.

The orthographic grid uses the original Frame `makeOrthoGrid` / `NavOrtho` mathematics. Main spacing is `10^ceil(log10(140 * millimetresPerPixel))`; minor spacing is one tenth. Density is measured in CSS pixels; scene units remain millimetres. Colored projection axes extend 1000 mm from world zero in their positive directions; their fixed length provides a scale reference while the gray grid remains adaptive. Generate only visible grid lines, keeping line count bounded by screen density. Compute phase in Float64 and upload small viewport-local NDC coordinates, avoiding large Float32 world coordinates and unsafe large-integer loop increments.

Perspective zoom/pan/orbit first use a visible mesh or spline point under the pointer. Spline navigation uses perspective-correct interpolation. On a miss, intersect a camera-normal plane through the last valid surface target. Before any surface hit, the finite XZ guide square is a fallback: 2000 x 2000 mm, with |X| and |Z| at most 1000. A grid hit does not replace the remembered surface. Open/replacement resets that target. GPU mesh picking may refine the initial analytic fallback asynchronously, without modifying an already completed gesture.

All views share one GPUDevice and each mesh's buffers. An inactive view retains its last color image and its own depth target; navigating one view does not redraw unrelated views. Scene, visibility or selection changes invalidate visible views. Release hidden-view resources. Orthographic and posed pipelines compile lazily and specialize static conditions. Quad dividers are topmost black overlays and never intercept pointers.

Default shading is Solid + Isoparms in Perspective and Isoparms in all three orthographic views. The cycle is Solid -> Solid + Wire -> Wireframe -> Isoparms -> Solid + Isoparms. Each view stores its own mode. Enabled generators consume their input profiles unless explicitly selected. Editable Spline Patch source cages remain visible in Isoparms even when another Patch is selected. Isoparms shows spline cages and ordinary polygon edges; Solid + Isoparms uses cage lines for spline surfaces and the same barycentric surface shader as Solid + Wire for polygon meshes. It must not add a second polygon edge pass. Transparent material passes are disabled in Wireframe and Isoparms. Transparent Solid + Isoparms uses non-indexed barycentric corners, like Solid + Wire.

Wireframe/Isoparms use the existing screen-bounded compute diamond rasterizer, with paged-part frustum culling. Preserve geometry and detail; do not hide edges through LOD. Wire thickness is measured in physical pixels. Perspective barycentric interpolation avoids black-filled clipped triangles.

## Transforms, pivots and the gizmo

- Object mode is the default. Vertex/Edge/Polygon buttons are mutually exclusive; clicking an active component button returns to Object mode. Browser and viewport select the same scene owners.
- Matrices use Float64 column-major X/Y/Z/translation. `world = parentWorld * local`. Apply a world delta only to selected roots when both an ancestor and descendant are selected. Reparenting preserves the full affine world frame, including skew; Undo restores parentage and frames.
- Canonical mesh positions are rest geometry. Whole-object/group transforms update small uniforms, bounds and revisions, without rewriting positions or indices. Preserve affine matrices instead of decomposing them into lossy TRS. Nonuniform world scaling of a rotated object retains shear. File matrices may reflect; interactive scale stops at a small positive invertible size instead of crossing through zero. Normals use inverse transpose and determinant sign.
- Component edits use existing GPU masks. Convert world delta into rest space as `inverse(world) * delta * world`. Picking, navigation, hover and overlays use the object's world matrix. Oriented dimensions are GPU reductions returning six bounds values, serialized and cached by selection, pose and geometry. Reject stale measurements.
- Pivot is a separate local matrix relative to geometry. Editing it changes neither vertices nor object world matrix. Derive the default from bounds until first needed, then freeze it before object transformation. Polar decomposition yields an orthonormal gizmo basis without accumulating shear. Instance/Cloner implicit pivots are at their authored origin. Instance and Cloner evaluate source geometry relative to the source pivot: translating the source does not change evaluated copies, while moving its pivot shifts their internal geometry in the opposite direction. Symmetry reflects the authored source frames about the Symmetry origin without subtracting the source pivot. With all axes off the source keeps its exact world frame.
- The gizmo is Frame r248's original three-in-one design: 35 original mesh sets, original colors, 0.5 opacity, triangle hit testing and original hit priority. White center means uniform scale; colored strips move axes; pale extensions scale axes; inner areas move planes; outer quarter arcs rotate. Nominal size is 75 CSS px; 2D World uses EXTFLAT 3.35, Perspective/Object uses EXT3D 10. Flat geometry is shared with `CURVE_GIZMO`; no duplicate flat vertex library. P/SR screen-plane shapes follow the original rules. Do not replace it with arrows, full rings or axis letters.
- Mirror the spatial parts toward the camera, freezing signs separately for each view throughout a gesture. Every viewport owns a clipped SVG projection. Cache its DOM by view/basis/pivot/size. Hover raises opacity to one. A press in an inactive view activates it first. Wheel, middle/right navigation, double-click and context menu pass through to that viewport. Spline controls, and a lone selected polygon vertex, take priority over overlapping center geometry.
- Object previews keep start world matrices; update only affected frames/bounds. Coalesce pointermove through RAF and apply the final pointer position on release. Coordinate Manager shares one cached result across fields. Analytic bounds dimensions avoid GPU reductions where possible; defer other measurements until release.
- During a transform each view lazily caches color/depth of stationary geometry. Restore it with a screen pass and redraw moving/intersecting neighbors in correct order. Include touching bounding boxes for coplanar ordering. Invalidate on camera/viewport/static geometry changes and release at gesture end. Cost is about eight bytes per visible physical pixel, without geometry copies. Moving the entire scene does not reduce geometry work. Transparency disables this background cache.
- Scale responds linearly to the farthest boundary from the pivot; uniform scale follows a fixed screen diagonal. A small positive minimum follows rest precision/world magnitude. Excess travel beyond the minimum is not accumulated, so reversing immediately grows the object, including after reopening HASH. Alt-axis scale keeps explicit skew where the gizmo handles that gesture. The normal transform threshold is six CSS px. Escape, pointer cancellation and window blur revert the gesture.
- Q toggles quantization; S toggles snapping. Enabling one disables the other, including API changes. Quantized Move is relative to gesture start; scale quantizes size change. Orthographic step equals the minor adaptive grid; Perspective uses one displayed unit. Draw rounds every new vertex, including its unpublished first point, to world-grid intersections; tangent endpoints use the same grid during pointer motion. The displayed tangent handle stays under the snapped pointer. Rotation steps are 10 degrees below 205 CSS px radius, five below 410, then one. Rotation guide circles have reduced 0.28 opacity and no labels. Skew step is 0.1.
- Snap Move seeks visible vertices within ten CSS px and otherwise uses the grid, with a ten-pixel screen acceptance threshold. Orthographic grid candidates remain aligned to world-grid intersections even with Object coordinates. Axis/plane constraints still apply. Scale snaps dimensions to the step. Release a previous candidate when the pointer moves away.
- Vertex snapping is lazy GPU compute. CPU only filters projected bounding boxes. GPU checks visibility/depth, distance and stable IDs for ties; selected geometry and hidden objects are excluded. Read back a 32-byte winner. Serialize requests and skip stale intermediate searches; do not maintain a full CPU spatial index.
- A completed Move of one vertex may weld it to a coincident vertex in the same editable owner. Spline tolerance is `max(1e-9 mm, abs(coordinate)*1e-12)`; keep the existing destination ID. Polygon tolerance is `max(1e-7 mm, abs(coordinate)*2.3841858e-7)`. Search, compaction and index remapping run on GPU, including texture-backed storage, with only three integer counters read back. Retain triangle/corner IDs, UV and material masks; a collapsed triangle may remain to preserve those IDs. Multi-vertex/object/handle moves do not auto-weld. Undo restores exact geometry/backend.
- P or L briefly toggles Pivot Edit; holding it during a gesture temporarily enables editing and restores the previous state afterward. Scale is disabled while editing the pivot. Auto Pivot chooses the farthest world-bounds corner from the camera without moving geometry.
- Coordinate Manager exposes Position, Euler Rotation in degrees and Size. World uses world frames; Object uses parent frame for Position/Rotation and object axes for Size/gizmo. Text, diagonal scrub, Enter/blur commit and Escape revert share native transactions. Numeric Size uses the same positive limit as the gizmo. Arrow keys in fields step by one, Shift ten, Alt 0.1, retaining special fixed steps. An animated parameter name remains scrubbable when it becomes a Curves button.
- Display units affect labels/numbers only. Rescale applies physical scaling once at root matrices. Internal units are millimetres; nm, micrometres, mm, cm, dm, m and km do not require rewrites of canonical GPU arrays.
- Ctrl object/group transforms make independent descendant geometry and hierarchy copies; copy plus motion is one Undo. Component Ctrl transforms copy only complete triangles: all three vertices in Vertex or all three edges in Edge. Otherwise no topology copy occurs. Shift+Polygon extrudes the perimeter with two wall triangles per edge; Shift+Edge creates connecting quads. Internal cap edges make no walls. Shift+Vertex is ordinary transform; Ctrl takes priority. Sparse topology operations still rebuild the affected mesh.
- Move feedback measures the actual SVG text bounds, with 4 px horizontal and 2 px vertical padding. Only numbers in the selected unit appear on dark labels, without axis/unit captions. Arrow keys over the viewport/browser move selected objects in the camera plane by one grid step; Shift multiplies by ten. Z frames selection in the viewport under the pointer; F frames a spline.

## Objects Browser, conversion and copying

New objects appear at the top; HASH preserves order. Group wraps selected roots, keeps their descendant branches and world frames, and occupies the first selected browser row. Its parent and initial frame come from that first row. The whole action uses one Undo transaction. Do not create an unrelated empty group for this command.

Browser Shift-click selects the inclusive visible range; Ctrl toggles. Selection updates touch changed rows/tags instead of walking every tag. Render the visible hierarchy through a linear parent index rather than repeated whole-array child searches. Reserve readable name space beside tags. Middle-button name/tag pan updates the existing clipped span and clamps its translation, without rebuilding rows, regenerating thumbnails, syncing geometry or triggering scene rebuilds. Vertical drag auto-scroll continues beyond the viewport even with a stationary pointer; speed grows with distance and RAF stops on release. Viewport selection expands folded ancestors and scrolls the selected row into view.

Only show applicable context actions. Hide Select Children when there are no children, To Spline Patch except for polygon meshes, Morph on unsupported owners and conversion on unsupported types. The browser object menu does not include Set Key. Soft/Hard belong in Curves and applicable spline menus.

C / Connect / To Editable processes compatible families:

1. Parametric curves become editable splines and selected curves connect as one spline.
2. Selected polygon meshes connect as one independent polygon mesh.
3. Parametric solids/generators first become separate editable spline patches with source children.
4. Multiple selected spline patches connect into one spline patch.
5. A single spline patch becomes a polygon mesh on the next C.

Thus one solid takes two presses to reach polygons; several solids take three: patches, connected patch, polygons. Mixed selections process each family in the same action. The completed result remains selected, including keyboard C and polygon Bevel; intermediate GPU publications must not clear the browser selection. Keep affine placement and authored segment IDs. Polygon concatenation transforms positions and rebases indices on the GPU, retains ordered material face ranges/masks and imported UV corners, and does not create instances. Use Morph Modelling before editing tagged topology; retain logical controls and adapt existing poses to the new reference. Topology conversion is one normal history transaction.

Instance stores a stable source hash. Cloner and Symmetry use child sources and derived occurrences sharing canonical positions, indices, topology, normals and lines. Frames, masks, IDs and bindings remain per occurrence; leases delay resource release. Source publication refreshes all occurrences. Source material/UV inheritance can be overridden by the generator. Disabled or failed generators expose sources; consumed operands retain their editing gizmo. Pure spline replicas share line buffers.

Matrix/Radial/Object Cloner supports count, spacing, step/offset, alignment, random PSR and seed. Spline placement uses sampled arc length and Parallel/Tangent frames. Surface placement is area-weighted and reproducible in a worker. Cache canonical positions/indices and CDF until geometry changes; Count/seed resamples without another whole-surface readback. The first N placements remain stable when Count grows. Maximum is 100000 derived copies per scene. Random rotation/scale acts around each copy's source pivot. Object Cloner uses the surface's local frame; source PSR does not move sample positions. Sampling does not reveal the source while pending.

To Editable turns a Cloner into a group with the same name/hash and editable mesh/spline children at evaluated positions. New meshes initially borrow source GPU geometry; the first geometry edit detaches only that mesh. PSR does not copy buffers. Nested generators evaluate child occurrences once, including all occurrences of a group/Boolean operand. Batched draw transforms use distinct buffers for static and moving passes in each view. Measure oriented occurrence dimensions in GPU batches of at most 1024 with bounded scratch/readback.

Ctrl+D, tree copies, Ctrl+drag and Ctrl+C/V share native copy transactions. Clipboard owns source-time canonical GPU positions/indices and compact authoring metadata. Later source edits do not change pasted geometry. Polygon Morph copies retain a separate GPU rest reference so deformation is not doubled. Copy Undo archives rest positions; Redo/HASH reapply the same pose. Clipboard is replaced on the next Copy.

## Splines, patch surfaces and library

The common pipeline is authored cubic Bezier cage -> resolver -> surface builder. A cage holds Float64 vertices, relative ha/hb handles, segments, sequences, soft/boundary flags, free handles and approximation angle. Extrude, Lathe, Sweep, primitives and Spline Patch all generate ordinary cages. The builder receives boundary geometry only. A Spline Cage has no primitive, text, Extrude, Lathe, Sweep, profile or axis provenance. A converted source has only spline approximation parameters. Resolved cells are a transient geometric cache, never an authoritative saved fill list: rebuild them from segments, including when a cage is detached or moved under a new Spline Patch. Ignore old saved source-cell lists when evaluating a cage. Translation/ruled families are recognized from controls.

The source algorithms are Frame r248's editor and surface builder: angular sampling, planar even-odd contours/holes, spatial two-to-five-sided cells, Extrude with flat/round fillets, Lathe poles and Sweep Parallel/Tangent transport. A small Float64 adapter replaces Three math; scalar cubic evaluation is shared with Curves. Kernels/fonts are embedded as nonexecuting text and parsed lazily. Pure polygon workloads start no spline workers.

Planar compatible translation/ruled quads use the original formula in one batched GPU compute pass. Nonplanar quads use the original adaptive surface builder, including interior curvature even when all four edges are straight. Boundaries and logical IDs remain canonical. General cells use the original adaptive Float64 worker builder, using up to `hardwareConcurrency-1` workers and no more than changed CPU cells. Keep a thread available to UI. No old CPU shading mesh, surface BVH or permanent main-thread triangle copy. Keep only authored cage and sampled controls needed for interaction.

Geometry edits rerun the resolver because planarity, nesting and filled regions depend on coordinates and tangents as well as graph incidence. When freshly resolved loops retain the same identities, keep their cell layout and segment-to-incident-cell indices, resampling/rebuilding only affected boundaries/cells and copying untouched canonical GPU ranges. Changed loops rebuild the surface. Graph, sequence, boundary or global approximation changes, first build and `spline.rebuild` require fresh resolution. Editor component-cell caches include actual vertices, tangents, sequences, approximation and Border flags; in-place drags cannot retain stale hole/cell loops. Scale traversal limits with cage size and report incomplete search/candidate overflow instead of publishing partial output. Planar graphs use the planar resolver. A complete orientable shell already found from planar regions needs no redundant spatial cycle search; all other spatial searches must complete within budgets scaled to the cage. Resolver guarantees are combinatorial, not an external geometric self-intersection certificate.

General incremental assembly copies unchanged canonical ranges GPU-to-GPU and remaps indices with the shared `remap index ranges` compute kernel. Transfer only changed cell geometry and boundary samples. Shared boundary vertices must stay shared. Reject stale scene/owner/revision tokens; fall back to full build when reuse is invalid. Compare incremental positions/indices with a fresh full build by GPU digests.

The coordinator cache is bounded to an estimated 64 MiB LRU by surface owner; helper workers retain only the current batch. CPU triangle cache bytes are zero after publication. Earlier per-lane caches were bounded to 4 MiB each. Limited sample/parameter caches reuse unchanged curves and normalize translated/scaled equivalents; they do not retain a full triangle mirror.

During a control drag the cage updates immediately, while workers publish coalesced current surface snapshots before release. At most one build is active; the latest state wins. Final release publishes the exact last edit. Undo/Cancel rejects delayed results and explicitly invalidates source/generators, including in-place changes. Whole-generator affine transforms reuse surface buffers; dependencies are measured in generator-local frames. Promise serialization must not retain retired build arrays.

An editable patch owns one editable spline child. That child owns cage and approximation; the parent owns the generated surface. The first C from a solid preserves its source accuracy. The second C bakes canonical polygon geometry and removes consumed source children in the same Undo. A supplied patch hash aliases its only editable source for inspect/replace/tangent operations; multiple-input mutations require an explicit source ID. Existing local embedded-cage fixtures normalize into this structure when opened and are not rewritten merely for tests. Disabling a patch hides its surface while keeping its spline visible. Removing its last source removes the old surface immediately.

Click with Draw Spline places points; drag creates free handles even before the first segment. Clicking the first point closes a sequence, except Ctrl always continues. Right-click, Enter or Escape ends drawing and keeps Vertex mode active. Orientation uses ordinary object affine frames. New drawing in Perspective lies in a plane normal to the camera. Top/Front/Right drawing follows the activated projection plane. Do not reorient a nonempty spline.

Ctrl-hover in Vertex finds the nearest actual projected cubic within ten CSS px. Refine its parameter on the cubic; do not substitute the nearest point on a coarse sample chord. Marker and inserted vertex use the same refined parameter; Ctrl release hides the marker. Ctrl-click on a second existing vertex connects it to the one selected vertex. Ctrl-click on a segment splits by de Casteljau without changing the curve or source-cell boundary. With a selected vertex, connect the new point to that vertex where needed. Ctrl-click/drag in empty space continues drawing in the existing spline, branching from a selected vertex; it does not create another spline object. This temporary drawing mode ends when Ctrl/Meta is released. Ctrl/Shift component drag retains the applicable Copy/Extrude path outside Morph Solve.

Vertex displays points on selected editable cages; tangent handles appear for selected vertices and every sibling at the vertex of a selected handle. Selecting both a point and its tangent gives the point priority for transforms, bounds and coordinates. Parametric splines select as objects. Curves retain their normal blue color; editable spline browser names are warm, parametric names blue. Control/handle picking radius is ten CSS px. Spline and polygon vertices, selected markers and tangent handles are 5 by 5 CSS pixel squares at every DPR; the picking radius is independent of the sprite size. Selected points are orange, hover light, tangents thin gray. Handle display scale is `0.5/0.5522847498307936`, leaving authored cubic controls unchanged. Solid modes depth-test controls; Wireframe/Isoparms display all.

Alt marquee selects controls of every selected editable spline/patch, including Shift addition. The shared gizmo and Coordinate Manager apply one world transform to all selected cages in their local frames. Aggregate bounds cover all selected controls. Ctrl+A over a viewport selects applicable cage/mesh elements regardless of prior Objects Browser focus. Empty clicks clear components according to selection mode. Delete/Backspace in the browser or outside the viewport removes the spline owner. Over the viewport, it removes selected controls/edges; Polygon mode removes the selected cage cells' boundary segments rather than the owner.

Ordinary tangent motion applies the same minimal rotation and length factor to sibling tangents, preserving length ratios and angles between branches. Ctrl/Shift makes the other tangents independent. Switching the modifier during drag latches the current relation without a jump. The same rule applies to free handles. Soft/Hard changes a chosen vertex's star without zeroing neighboring vertices' handles. Offer Soft for mixed/hard selections, Hard for all-soft; Equal Tangents requires nonzero handles and averages both opposing vectors rather than choosing a master tangent. At branch vertices it equalizes lengths while preserving branch directions. Object coordinates align X along selected tangent/chord and choose a stable local plane; World remains axis-aligned.

Patch Polygon mode selects authored filled cells, including holes, rather than generated triangles. Their segment boundaries drive edge selection, transformations, Outline and other boundary tools. Cells and oriented multi-loop boundaries come from the ordinary geometric resolver. Toggle Border matches r248: it sets all explicitly selected segments when any is unmarked, and clears them when all are marked, across active editable owners in one Undo transaction. Marked borders remove the smaller connected fill region; clearing them restores ordinary resolution. Hovering a filled cell in Polygon mode highlights its segment boundaries. Generated surface arrays and saved source-cell lists are not cage authoring data. Polygon Shift extrusion keeps the translated cap, replaces the original cap with side walls along the selected region perimeter, and transforms the new vertices even while the connecting rails initially have zero length.

Library: Square, Circle, Polyhedron, Text, Helix, Gear, Pulley, Cube, Cylinder, Tube, Sphere, Capsule, Nut, Washer and Bolt. Hardware uses original dimensional tables, T-slot/rivet nuts, toothed/split washers and eight screw/bolt families. Names include DIN/type, thread and bolt length (for example DIN 912 M3*20), retaining user renames. Pulley profiles are GT2/GT3/GT5/H3M/H5M. Gear uses a 20-degree involute and adaptive cubic Hermite fitting with a module * 0.008 positional tolerance per tooth side and exact pitch-circle knots; tool undercut is not modeled. Car, Tree and Human load original local Frame models on demand, retaining poses, detail options, colors and material slots. Droid Sans data is embedded and decompressed on first Text. Camera is not in Objects Library; use the bottom camera button.

## Modeling kernels

### Outline and Bevel

Outline uses the original Float64 planar/spatial Frame r248 kernel, including winding/holes, offset fitting, joins, cleanup and Bishop-frame spatial paths. That mathematical kernel already matched the referenced old editor; integration must pass the intended selected boundaries and invalidate stale source-cell topology. Select explicit edges/cell boundaries, or segments with both endpoints selected, rather than every edge incident to one selected point. Preserve unrelated segments.

Outline has only signed Distance in Attributes, without an Outline header or Done button. Numeric input, diagonal scrub and viewport diagonal drag use the same worker session prepared from the original cage. The signed screen projection (dx - dy) / sqrt(2) increases up/right and decreases down/left continuously through zero; the perpendicular diagonal contributes nothing. Branched selections are processed as independent paths ending at their junctions, retaining shared authored vertex IDs through cleanup. Finishing Outline retains the original vertex selection. Provably disjoint contour bounds are separated before winding tests; nested counters/holes stay together. Coalesce intermediate distances; each completed gesture has one Undo. Alt marquee remains available. Enter/Escape closes the tool; Escape during a gesture reverts it. A subsequent viewport action after a completed adjustment returns to ordinary selection.

Bevel reuses the original `prepareEdgeBevel` / `applyEdgeBevel` / topology completion for polygon/patch edges and `planSplineVertexBevels` / `applySplineVertexBevels` for pure 2D/3D spline corners. Spline corner trimming is arc-length based and contact-limited. Interactive Bevel always rounds its profile; Size is its only attribute, with no Apply/header UI. The geometry.bevel API defaults to round:true and accepts an explicit profile mode for scripted construction. Numeric/diagonal/viewport drag recomputes from the saved base; zero restores it. Worker previews coalesce and a gesture creates one Undo. Polygon previews always recompute from the same original geometry, including repeated numeric edits and zero. The next viewport action after a completed adjustment exits Bevel and restores ordinary mouse input. Patch edits update the cage; polygon edits use the common native upload/surface path. Topology-changing polygon bevel discards obsolete face masks but keeps whole-object materials. Edge API IDs are spline segment IDs or `minVertex:maxVertex`; absent polygon IDs choose geometric creases.

### Polygon editing and Boolean

Mesh tools include Ctrl-click Add Point inside a face/on a shared edge, screen-polyline Line Cut, Loop Selection, soft selection, Bridge between equal-length boundary chains/loops, Close Polygonal Hole and Connected. Add Point is absent from polygon context menus. Line Cut has only Visible Only on/off in Attributes, commits with right-click or Enter, and cancels with Escape; Visible Only derives its face bitmap from the native GPU surface ID pass. Soft Selection has only Radius. Loop Selection has no Attributes, previews the edge loop under the pointer before selecting it, and exits on Escape or another operation. Selected polygon edges use the same green as spline-patch borders. Add Point keeps selection without a new yellow object flash. GPU topology operations preserve logical ownership and publish atomically; invalid requests must fail before scene mutation. New UV corners start at (0,0) while existing corners and masks retain applicable IDs.

Boolean is a generator over ordered operands and all nested occurrences. The toolbar creates an empty Boolean; explicit API inputs reparent children. Disabled/incomplete/failed Boolean exposes operands and removes obsolete output. Moving an operand out restores its unchanged canonical arrays. Volume Boolean was removed; no method/resolution UI/API. General intersections use the original surface worker; disjoint eligible buffer meshes without face masks concatenate on GPU without geometry readback.

Compare inherited boundary/nonmanifold defects with the result using exact Float32 edge endpoints. Worker BVHs accelerate multi-ray classification. After three seconds display a short stage and elapsed seconds in the top left viewport corner, including preparation/publication time. Clear it on every completion/error/stale result. Do not invent percentages.

## Materials, UVs and light

No material tag means immutable Default: sRGB gray 0.5, roughness 0.5, metalness/emission zero and opacity one. Fast/default and explicitly assigned Default render identically. Editing Default creates a separate material. A first imported material is editable; list position zero does not make it Default. New materials start from the actual Default rather than an imported library entry.

Material tags own polygon masks; there is no separate S/selection tag. In Polygon mode, dropping material on selected faces assigns a private bitmap. Otherwise it applies to the whole owner. Viewport drops use a real GPU ray pick in every mode/view without altering selection or being blocked by the gizmo. Dropping on an existing tag replaces material while retaining its mask. Masks may overlap; the rightmost tag wins. A tag's context action selects its polygons. Deleting a tag removes mask ownership from active/saved data; history may retain the GPU bitmap. Copies get independent masks/UV while sharing the material library. Masks take one bit per source triangle; derived tables avoid a uint32 per face across the scene.

Material Editor retains the established 256 px sidebar layout. Map slots appear to the left of Emissive, Roughness, Metalness, Opacity, Normal and AO; base map remains on the color preview. Filled slots show a preview/cross and remove by one click; empty slots open a chooser. Context menu replaces a map and chooses R/G/B/A/Luminance for scalar maps. ORM/ARM imports use one image for AO/Roughness/Metalness with R/G/B channels. Packed assets are not duplicated. Normal strength appears only with a normal map; AO appears only for UV-bearing material owners and has no numeric field. Deleting the last relevant UV tag hides AO; Undo restores it.

Loading base color with alpha links the same asset to Opacity A without squaring alpha. Deleting linked base clears linked opacity; deleting opacity alone disables embedded base alpha. Other packed channels remain. glTF OPAQUE ignores alpha, MASK uses cutoff and BLEND uses coverage. Path-traced coverage holes do not refract; native Opacity without glTF coverage represents transmission. Viewport, render and GLB export agree. Scalar material dragging steps by one; Emissive retains its increasing step and typed fractions work. Palette swatches are 15x16 px, adjacent fields 48 px; only parameter texture buttons are shifted upward one pixel, with a one-pixel horizontal gap before their labels.

Viewport maps use one RGBA8 texture array with maximum side 1024. sRGB color/emissive and raw normal/MR/AO/opacity use different views of the same allocation. Save original encoded images. Normal is tangent-space RGB with strength (`bump` is its historical API field), not a height map from base color. AO affects environment/indirect light only and requires imported UVs. Transparency is weighted blended OIT without CPU sorting or premature HDR clipping; it is approximate multilayer blending.

Imported UVs are per triangle corner and preserve seams. UV Edit/projection use the common gizmo and history. OBJ vt creates a UV tag; glTF only creates one when a used texture references that TEXCOORD. UV-tag selection does not change the manager tab. Projection is a canonical Float64 affine frame. UV readback is explicit and bounded.

Viewport lighting is one world-space procedural environment: neutral hemisphere .035-.26 and three normalized flat-top super-Gaussian softboxes. Default directions are normalized [-1,.8,.1], [.7,.65,-.4], [.1,.85,1]; sharpness 56/48/64 and energies 1.04050/.78037/.91043. All are above the horizon. Diffuse cube is 32 squared; specular cube 256 squared with nine mip levels, about 4.05 MiB total. Prefilter only after effective light direction/parameters/enabled state changes. Translation, scale, unchanged-direction roll, materials, camera and ordinary frames do not rebake. Pixel shading uses two environment samples, Schlick Fresnel and simple diffuse/metal/emission arithmetic. Roughness selects a mip; dielectric F0 is .04 and grazing response retains integrated BRDF filtering. Stable dither is about half an output LSB.

Infinite Light is native object discriminator two without mesh buffers. It starts at world [0,0,0], independent of the current gizmo or selection. Its local +X points along emission; the environment lobe points along -X. Position moves only the helper. Attributes are intensity, temperature K and angular size; intensity is linear, size is full width at half intensity, 6500 K is neutral [1,1,1]. Lights occupy default environment slots in tree order and additional lights add lobes. Green enabled controls illumination; red visible controls helper independently, including ancestor flags. Hidden helper does not extinguish light; disabled illumination retains helper. Delete releases its slot.

Camera and light helpers are slightly smaller, appear in every visible view and stay above render previews. Visible camera paths have a matching transparent ten-pixel picking stroke, and light paths use the same technique. An active camera helper is hidden. Other cameras show rectangular pyramids along +X. Helpers are controls rather than triangle meshes.

Target links any ordinary object, camera or light by stable hash. Aim its pivot's local +X at the target using the shortest rotation, preserving authored stretch and pivot position. Do not add world-up roll correction. Disabled Target restores the authored orientation. Deleting Target freezes the surviving object's current evaluated orientation. Dragging an active view camera's Target keeps the press projection until release, avoiding a moving coordinate frame under the pointer. Parent/target dependencies reject cycles before mutation and reevaluate during transforms/animation.

## HASH native scene

`.hash` is the canonical addressed scene model in RAM: `scene.records` maps address to type/value. Geometry values are owner-bound GPU descriptors with current counts, not CPU arrays. Compress only for Save. Add fields/types only for an actual authored feature after deciding ownership, precision, serialized size and exact round-trip checks. No speculative catch-all data container.

Record header is 26 bytes: uint16 TYPE, sixteen-byte ID and uint64 byte length, little-endian. Property addresses are object ID XOR property ID. Low types are bytes (0), uint32 (3), IDs (4), float32 (5), float64 (6), UTF-8 text (7). Compression flags select record gzip and prediction. Float32 positions use same-axis bitwise XOR and byte planes; indices use local delta/ZigZag/LEB128 before gzip. Keep raw when compression is larger. Separate independent meshes keep separate position/index records even if topology matches; gzip sharing does not imply instances.

Store object order, names, parent, visibility/enabled/folded, lights, materials, assets, tags, UV, projection, camera/view layout, affine frames, pivots, units, source cages/parameters, animation and Morph authoring. Omit computed normals, shading aliases, adjacency, edges, temporary selection/hover, ID maps, bounds and history. Load HASH without repeated STL weld/cleanup: every Float32 bit, index and logical vertex identity must survive.

`matrix`/`pivot` are twelve Float64 values (three linear columns plus translation), omitting the fixed fourth row. Identity object matrices and unneeded derived default pivots may be omitted; explicit pivots are retained. `units` is two byte indices and mm/mm may be omitted. World/inverse/rigid frames, GPU uniforms, dimensions and bounds are caches. Camera uses its existing Float64 record: twelve perspective values, optional three orthographic center-U/center-V/half-height triples plus active index/single flag (23 total), and optional four shading indices (27 total). Validate lengths, finite values, inversion and parent cycles.

Spline address is `60ff567f12db4fbea03cf36d8170f725`, low TYPE bytes. SLP1 stores subtype, typed named parameters, optional cage, version/counter, Float64 controls, local string IDs, endpoint/sequence indices, flags and free handles. SourceCells v4 add oriented edge loops. Validate sizes, finite coordinates, unique IDs and sequence ownership/connectivity. Pure spline is a group discriminator with spline data; a generated solid is a mesh owner with spline data. Save source parameters/cage and rebuild derived triangles on Open. A baked polygon mesh saves its canonical arrays.

The existing `parameters` text address stores versioned authored animation/Morph/library metadata as JSON. This is the intentional authoring exception to the older blanket prohibition on JSON; typed cages, materials and geometry remain binary. Do not serialize derived surfaces in that metadata.

Material/asset roots list IDs. Owner tags preserve order. Material records store name, fifteen Float64 scalar/channel/alpha/AO values and eight image IDs: color, opacity, emission, legacy MR, roughness, metalness, normal, AO. Material tag references a material and optional bytes faces mask under the same tag ID. UV tag owns Float32 per-corner UVs; projection uses Float64[12]. Infinite light uses discriminator two and Float64[3] intensity/K/angle. Assets store original encoded image bytes or relative UTF-8 paths. GPU tables/cubemaps/atlas/OIT/UV mode are never serialized. Existing local short material payloads are still read; do not build a migration framework.

Save blocks mutation, stages at most 4 MiB per GPU readback and keeps temporary memory to the current array/packing. File System Access writes records sequentially; Download retains only compressed Blob parts. Open indexes the Blob without loading it all, preflights payloads one mesh at a time, then releases the old GPU scene and uploads one mesh at a time. This two-pass design detects corrupt files before discarding the current scene without requiring two enormous scenes in VRAM. Limits are 512 MiB decoded per record, 100000 objects and 1000000 records; expand together with real streaming work.

Open, Save, Save As, Save Incremental and Download use native scenes. Save As offers HASH, binary STL, GLB, binary PLY, binary legacy VTK and compressed 3MF. The format menu opens on mousedown and supports press/drag/release selection. Open lists only supported scene extensions: HASH/STL/OBJ/glTF/GLB/PLY/VTK/3MF/SVG/STEP/DXF; auxiliary buffers/images are not advertised as standalone scene formats. Empty startup has no Scene object, automatic STL import or spline workers; empty HASH saves/reopens. `?scene=...hash` and Share fragments explicitly load scenes. Ctrl+O/Ctrl+S use the same actions. Dropping a scene into a nonempty scene shows two context-menu rows, Open and Merge. Open replaces; Merge appends native objects/materials/UV/authoring with remapped identities and one Undo, retaining the view and existing active camera. An empty scene opens directly. Image drop adds a texture or assigns it to the dropped object/material slot.

Merge reuses the normal native decoders, resource owners and structure/copy transactions. It must not reload/re-encode the original scene or make a second CPU scene model. Imported HASH identities and references are re-addressed; source geometry remains independent. Failures restore the prior published structure and release newly uploaded meshes.

## Import, export and assets

STL/OBJ use short-lived parser workers and transferable buffers. Binary STL imports one object at source scale, maps Z-up into Y-up, exact-welds on CPU and cleans within ten Float32 ULP per coordinate on GPU. Representatives are actual source points and tolerance cannot chain-grow; drop collapsed triangles. A deliberately small source STL stays small in a 100 mm workspace; F explicitly frames it. Never multiply ordinary imports or create a stress matrix in runtime.

Embedded freestanding WASM SIMD is lazy in workers. STL batches 32768 triangles for Float32 bit conversion/validation and grows an exact-weld hash table. JavaScript remains the fallback for small/unsupported/arena-limited input. Float64x2 affine work keeps double intermediates without FMA/quantization. Rebuild with `tools/stl-simd.c` and `tools/build-simd.mjs` (`CLANG` may select a wasm-capable compiler). Experimental f32 affine kernels are not a replacement for validated Float64 geometry.

OBJ coordinates are millimetres. Support negative indices, vt, backslash line continuations, concave polygon ear clipping, contour-bridge duplicate points and alternate projections for nonplanar exporter polygons. Triangle records retain their source indices, including degenerate pole triangles. Mixed textured/untextured faces retain supplied UVs and initialize missing corners to zero in native UV coordinates. The supplied vase is one mesh with 115740 logical vertices / 229682 triangles, unchanged input file.

Native glTF/GLB 2.0 supports JSON/GLB chunks, external/embedded buffers/images, interleaved/normalized/sparse accessors, indexed/nonindexed triangles/strips/fans, matrix/TRS hierarchy, metres-to-millimetres and no axis swap. One mesh node becomes one native mesh; combine its primitives with exact position weld, per-corner UV seams and ordered primitive material masks. Repeated mesh nodes remain independent objects and no synthetic Scene wrapper is added. Support PBR factors, base color, emissive, MR, normal, AO, alpha and KHR_texture_transform. Bake emissive RGB factors into the image; do not turn scalar emission into a uniform emissive surface. Required unsupported/compressed extensions or unbaked skinning reject before scene replacement. For local glTF select its bin/images together or use one GLB; URL resources must remain same-origin.

Path-traced UVs follow corners through BVH triangle reorder and image upload orientation. Wait for maps before snapshot. GLB export writes visible evaluated surfaces, groups/hierarchy, affine frames, normals, UV seams, PBR/alpha and embedded images; mm becomes metres. Bake packed scalar/alpha maps when needed and reuse compatible existing assets. Preserve original PNG/JPEG bytes; encode other image types as PNG. Spline/Morph authoring stays in HASH. STL writes visible evaluated triangles and occurrence matrices in 4096-triangle blocks, reverses the import axis mapping, computes final normals and flips winding for reflected frames; hidden/consumed operands and curves do not export. Read at most one mesh transiently.

Car/Tree/Human GLBs derive from original Frame r248 HASH geometry/material slots. Test-only Khronos assets retain attribution/license files in their folders. PBRT v4 FastOwenScrambler attribution/Apache-2.0 text remains embedded, as do original Droid Sans data. Playwright 1.64.1 is a development dependency only.

### VTK, 3MF and SVG interchange

VTK is for polygon surfaces from scientific and scanning tools. Its native worker reads legacy POLYDATA in ASCII or binary big-endian, with float/double points, polygons, triangle strips and VTK 5.x OFFSETS/CONNECTIVITY arrays (including 64-bit IDs). Unrelated lines/vertices, FIELD data and metadata blocks are consumed; point/cell scientific attributes are not retained. Volume grids, XML VTK and point-cloud-only files are outside this importer. Export shares PLY's bounded indexed-mesh writer: visible evaluated surfaces, world/occurrence matrices, reflected winding, exact Float32 positions, 4096-record chunks and binary big-endian VTK 3.0. No automatic axis or scale changes; units are millimeters, Y-up.

3MF is for print-oriented interchange with physical units, named parts, assemblies and material colors. Native ZIP/ZIP64 reading supports stored/DEFLATE parts, central-directory/local-header validation, data descriptors and CRC32. XML, meshes, indices, units, component references, required extensions and transforms are checked before scene replacement. Core meshes, nested components, repeated build items, production part references, base materials and uniform color groups use existing native owners/material masks. Source Z-up becomes Frame Y-up with the same right-handed mapping as STL; supported units include microns, mm, cm, inches, feet and meters. Mesh occurrences remain independent editable geometry. Required unsupported extensions, referenced texture/composite properties and vertex color gradients reject. Images, slicer profiles and arbitrary metadata are not imported.

3MF export streams a compressed OPC package with the browser's DEFLATE implementation and a native ZIP writer. It retains visible evaluated parts, names, physical placement, native grouping, base colors/alpha and per-face material assignments. Native groups become component objects so an assembly remains distinguishable from independent build items. World transforms are baked into Float32-readable coordinates; reflections reverse triangle winding. Existing GPU edge diagnostics distinguish closed model meshes from open/nonmanifold/degenerate surfaces; no mesh repair is performed. Texture/PBR maps, slicer settings and authoring remain in GLB/HASH. Temporary readback is bounded to one mesh resource array plus face-material IDs, with 4096-record XML chunks; output can stream directly to a writable file. Import limits are 256 MiB per package part, 512 MiB decoded parts, 100000 objects and component depth 64. Export currently uses classic ZIP, limited to 4 GiB.

SVG is for editable logo/profile contours and native Extrude inputs. It imports path M/L/H/V/C/S/Q/T/A/Z commands (absolute/relative, repeated arguments and compact arc flags), lines, polylines, polygons, circles, ellipses and rounded rectangles. Group transforms, viewBox/meet/none alignment, absolute physical units and internal use references are applied before creating native XY spline cages with an authored +90 degree X frame, placing them on the world XZ plane for Top view. SVG right maps to +X and SVG down maps to -Z. Pixels use 96 dpi. Cubic curves remain cubic; quadratics convert exactly, and elliptical arcs become cubic pieces of at most 90 degrees. Compound subpaths remain separate sequences. HASH preserves the exact imported cage. Fill/stroke styling is not expanded into geometry; text/raster images, root transforms, nested viewports, symbol viewports, clipping/filter effects, geometry CSS and external references require outlined/baked vectors. Scripts are never executed. Limits are 64 MiB SVG, one million segments, 100000 owners and reference depth 64.

Open, file chooser, drop, Merge and frameAI share these decoders and native transactions. Save As, Download, incremental Save and scene.export share the VTK/3MF writers; streaming saves lock editor mutation and always release the lock on success/failure. scene.export adds formats vtk and 3mf; scene.open/merge also accept SVG and STEP/STP. No external runtime library or loader is used.

Focused verification: tests/print-formats.mjs uses ten upstream VTK and thirteen upstream 3MF files; tests/svg-import.mjs uses twelve upstream SVGs. Source URLs, pinned revisions, SHA-256 and licenses are stored beside the fixtures. Independent Python ZIP/ElementTree and a separate VTK reader verify source arrays, assemblies, matrices, units, colors and emitted geometry. SVG coverage is checked bidirectionally against browser SVG geometry and exercised as a native Extrude profile. Tests cover exact HASH/geometry roundtrips, real chooser/drop/Save As writes, Merge/Undo, corrupt input atomicity, CRC, required extensions, CPU/GPU frame timestamps and completed-operation latency budgets. Both modules run in standard and stress profiles.

### STEP to ordinary Spline Patch or polygons

STEP/STP Open and Merge use an in-house Part 21 reader, temporary polygon geometry and the same engineering recognizer as `mesh.toSplinePatch`. Each completely recognized part becomes an ordinary `spline_patch` with one editable `spline` source. Parts that cannot be completely recognized or whose native cage cannot reconstruct the shell remain ordinary polygon meshes. One file can contain both representations; no partial face conversion is published within a part. A patch source contains only standard cubic vertices, segments, handles and sequences, with the ordinary approximation angle. No STEP entities, surface equations, face groups, trim loops, fixed cells, NURBS weights or custom parameters are saved in the cage or HASH. There is no new spline property version. Temporary STEP face-group hints are discarded after recognition. Original polygon buffers are transferred back from the recognizer without copying and uploaded only for polygon parts; they are discarded for successful patches. Polygon fallback uses normal GPU ownership, with no persistent CPU geometry mirror.

The reader handles simple/complex entities, references, comments, escaped strings, SI/conversion-based length units and CAD Z-up to Frame Y-up. Its geometry subset includes B-rep solids/shells, planar faces with holes, and rectangular parameter trims of cylindrical, conical, spherical, toroidal and knot-defined rational/non-rational B-spline surfaces. Boundary curves include lines, circles, ellipses, knot-defined B-splines and surface/seam/trimmed wrappers. This is geometry import; CAD feature history, presentation colors, PMI and constraints are not imported.

This is a bounded initial subset, not complete AP203/AP214/AP242 coverage. Non-rectangular curved trims, mapped/transformed assemblies, mixed representation units and unsupported curves/surfaces reject before scene replacement. Interior probes also check the temporary mesh against the STEP surface, including a regression with planar boundaries and a curved NURBS interior. Recognition retains the original polygon part when any face is unrecognized, compact reconstruction fails, or reconstruction of a closed shell is not closed. Complete-part recognition skips fragment searching and avoids constructing a discarded per-triangle cage. Failed Open/Merge preserve the current scene. The toroidal corpus example imports as polygons; the mapped-assembly example remains an explicit parser rejection test and is not counted as a successful import. ### DXF geometry interchange

DXF Open, chooser, drop, Merge and `scene.open/merge` use the same short-lived native parser worker and existing publication/history transactions. No runtime dependency or external CAD service is used. Curves become ordinary editable cubic `spline` cages; polygon surfaces use ordinary canonical GPU meshes. Layers batch geometry into native owners below a filename group, retaining off/frozen layers and invisible entities as hidden owners. INSERTs are expanded into editable geometry with complete affine products, including nested shear, reflection, nonuniform scale, nonzero block origins and MINSERT row/column arrays. Layer 0 inherits its insertion layer. Cached DIMENSION blocks are expanded; dimensions are not regenerated from measurement parameters.

The reader accepts ASCII-compatible text, UTF-8 (R2007+), UTF-16 with BOM, CR/LF/CRLF, DXF Unicode escapes, legacy ANSI codepages and common DOS codepages, including Cyrillic and Japanese. Binary DXF supports the 22-byte sentinel, legacy one-byte/escaped group codes and modern two-byte codes, strings, numeric types, binary chunks and XDATA. An unknown declared codepage falls back to Windows-1252 and is reported; damaged text characters use the decoder's replacement character. Minimal files may omit HEADER/TABLES and a final EOF marker when all sections are complete. Reactors, extension dictionaries, XDATA, unrelated sections and trailing producer data after EOF do not become geometry. Geometry syntax, references, counts and finite coordinates still validate before replacement.

Supported geometry includes LINE, ARC, CIRCLE, ELLIPSE, LWPOLYLINE with signed bulges/elevation, 2D/3D POLYLINE, polygon grids, polyfaces, 3DFACE, SOLID, TRACE, MESH control surfaces, SPLINE and LEADER centerlines. HATCH imports its polyline/line/arc/ellipse/spline boundary contours, including clockwise complementary angles; fill/pattern strokes are not generated. NURBS support rational weights, arbitrary nondecreasing knots, periodic/unclamped vectors and degrees 1–25. Adaptive cubic fitting checks interior samples against the source curve in transformed millimeters, with tolerance `max(1e-5 mm, transformed control extent * 1e-7)`. Circular/elliptical arcs use cubic pieces of at most 45 degrees. Fit-only splines use chord-length natural cubic interpolation, respecting supplied end-tangent directions. Discontinuous knot spans and disconnected hatch edges remain separate sequences without invented bridge lines. Open boundary fragments are preserved and reported. Legacy fitted POLYLINE uses supplied generated samples when available, otherwise its control polygon; both approximations are reported.

`$INSUNITS` applies physical scaling exactly once to millimeters, including inches/feet and US survey units. Unitless/absent units mean millimeters; `$MEASUREMENT` is not treated as a physical unit. ## Printer GPU LDI coverage preview

Slice builds and cleans two persistent layered depth images along printer-local X and Z, covering every layer of the evaluated model. The runtime stays in one `plugins/3d-printer/plugin.js` on the shared native GPUDevice. Canonical buffer/texture geometry, evaluated occurrences, affine frames and visibility come from the ordinary scene snapshot. Source positions, indices, raw depths and cleaned intervals stay on GPU; runtime readback is 56 bytes of bounds and allocation/diagnostic counters. No triangle-plane section buffers, vector contour arrangement, perimeters or toolpaths are generated.

The GPU first reduces local model bounds, then triangle-centric projection emits depth/occurrence events into the two ray grids. Conservative projected bounding boxes, canonical triangle ordering, shared-edge interpolation and half-open section endpoints cover shared triangle edges independently of winding. A hierarchical GPU prefix scan allocates ray event ranges. Each ray sorts at most 1024 depth events, collapses only bit-identical depth/plane events within one occurrence, applies even-odd parity within that occurrence and unions the active intervals across occurrences. Thus nested shells in one mesh retain cavities/islands, while separate intersecting or contained solid occurrences unite. Coordinates alone cannot distinguish a redundant contained solid from a cavity inside one occurrence; occurrence ownership defines this convention. Cleaned intervals are ordered, disjoint and clipped to X/Z [-500,500]. Local +Y remains the build axis, restricted to [0,1000].

Layer 1 is sampled at Initial layer height / 2; subsequent centers use Initial layer height + (zeroBasedLayer - 0.5) * Layer height. Horizontal samples cover the model bounds intersected with the build volume, with a requested pitch of 0.2 times Line width. Each horizontal dimension is capped at 2048 samples; the combined X/Z ray count across every layer is capped at 4194304. The pitch increases explicitly when necessary, and status.grid reports min, pitch, targetPitch and resolutionLimited. All layer rows are retained. This sampled coverage representation does not certify subpixel features, exact vector topology or the former 0.02W contour simplification bound. Nearby distinct depth events retain their parity. Duplicate detection requires identical Float32 depth and plane slopes after canonical triangle ordering; it never welds a thin overlap using a depth tolerance.

An ambiguous axial ray is excluded from the vote; one balanced direction supplies coverage, while two ambiguous directions leave the texel transparent.
