# Scene Control: common data and parameter authoring

## Shared parameter authoring for Scene Control (2026-11-08)

The common field adapter now permits explicit authoring of Cube size x/y/z (canonical millimetres, minimum zero) and Atomic Temperature (degrees Celsius, minimum -273.15), Damping (inverse picoseconds, minimum zero), Time scale (fs/s, minimum zero), Confinement (eV/angstrom, minimum zero) and Color. This is a bounded foundation for Scene Control, not its executable runtime or control-panel UI.

One declaration supplies field discovery, canonical units/ranges, native Attributes constraints, generic scene.update validation and Atomic settings schema. Native display-unit conversion is unchanged. Numeric Attributes clamp to declared bounds; API writes reject out-of-range values. No physical upper limits are invented. Other scalar fields remain observable read-only. Animated parameters are read-only current observations with writeUnavailable=animated-field; observedFrame never certifies completed simulation.

fields.write accepts one to 128 distinct targets using each field's epoch/revision. All values and targets are validated before publication, and mixed native/Atomic/metadata edits use one ordinary Undo transaction without selecting their owners. No-op batches create no history. Native history and document replacement invalidate stale CAS state, including ABA edits. HASH retains the ordinary parameter values and typed binding references, without a second scene model or extra stored runtime state.

Focused tests: tests/scene-field-writes.mjs and tests/scene-field-writes-browser.mjs (explicit --headless; optional --offline). The browser case uses a three-atom Atomic world and native Cube, tests UI/API/Undo/HASH/duplicate and bounded operation times, and checks native WebGPU errors. It is not an Atomic physics benchmark or a full Scene Control implementation. Existing source/schema records remain inert. Unite is excluded from qualification.

The following sections document the earlier data-only milestone. Their read-only parameter limitation is superseded only for the explicitly declared fields above.

## One native representation

The existing root `FrameHash.K.parameters` JSON and ordinary object's native `parameters` JSON may contain `authorData`. There is no new HASH address, second scene graph, plugin slot, database, source import, or external inference provider. Existing native XOR address ownership guards remain unchanged. Scene Docs and all four Docs editor files are unchanged. No new interface or service-worker resource is added. Only the title/meta and service-worker release stamp change together.

An envelope is `{version:1, revision:<nonnegative safe integer>, records:[...], retired?:[<32 lowercase hex IDs>]}`. Runtime epochs are never stored. Each record is `{id, revision, name, kind, refs, payload}`. Identity is `(owner, record id)`, not record name. Owner is the exact native object hash or the literal `scene` for the root namespace. Duplicate record IDs in one owner reject; the same record ID in different owner namespaces is valid. New records start at revision zero, changed records increment exactly once, unchanged records keep their revision. An envelope edit increments its revision once. JSON key order is canonicalized, not treated as a semantic edit.

Supported payloads:

- `source`: `{language:'javascript'|'html'|'css'|'text', text:string}`. Text is inert and retained exactly, including Unicode and line endings.
- `schema`: `{format:'json-schema', definition:object}`. This is an inspectable inert declaration, not an active schema validator or implemented custom Attributes provider.
- `binding`: `{target:integer}` indexes one field reference in the record's `refs`. This is an authored binding definition, not a running subscription or two-way UI binding.
- `opaque`: `{format:nonempty string, version:positive integer, data:JSON}`. The entire payload is preserved without interpretation. Only the explicit `refs` manifest has reference meaning.

Envelope version 1 is the entire compatibility contract. Unknown record kinds, unknown envelope keys and unsupported envelope versions reject. Declared opaque payload formats/versions can be retained, including nested unknown values. This is not a promise to preserve arbitrary undeclared HASH records or infer references from unknown strings. Source, schema and opaque payload strings, comments, `$ref` strings, filenames and hash literals are never rewritten.

Limits apply per envelope: 512 live records, 256 references per record, 4 MiB encoded JSON, 1,048,576 UTF-16 code units per string, 100,000 JSON values, depth 24, 256-code-unit keys, and 4096 retired IDs. Metadata names are at most 256 code units. Safe finite numbers and well-formed Unicode are required. Dense arrays and own enumerable data properties on plain or null-prototype objects are accepted. Cycles, functions, accessors, hidden/symbol properties, unsafe prototype keys and custom instances reject before serialization. `toJSON` is never called. Proxies and direct foreign-realm object input are not a supported transport; use JSON messages, not live cross-window objects.

Deleting records uses replacement without those records. Their owner-local IDs remain in `retired`, preventing accidental reuse and retargeting. Deleting the last record keeps a revisioned empty envelope/tombstones; a fresh ID is required to create a different record. Native Undo restores the original live identities and content revisions. Within one document, trusted history restoration unions allocated/retired identities into the restored envelope, excluding IDs restored live. Allocation reservations do not rewind across branches. The complete root and affected-owner unions are preflighted before history stack movement or native publication; exceeding 4096 retired IDs rejects without partial restoration. A saved post-Undo HASH retains this ledger. Full Open/New is an authoritative new document epoch and does not carry reservations from the prior document. Old scenes that never had author data retain absence, not an injected empty container. There is no separate destructive container-reset operation.

## Typed reference policy

References have exactly one of these shapes, with optional `unresolved:true`:

- `{kind:'object', owner:<native hash>}`
- `{kind:'field', owner:<native hash>, field:<stable field key>}`
- `{kind:'record', owner:<native hash>|'scene', id:<owner-local record ID>}`

Names, session-local UI IDs, indices and selection are never resolution fallbacks. An owner deletion makes a stored reference unavailable without deleting the definition. Restoring the exact owner/record via Undo resolves it again. A deliberate fresh-CAS edit can replace a reference or clear an unresolved marker; inspection never silently clears it.

Native Duplicate remaps object owners only within the copied set, keeps local record IDs under the new owners, and shares scene-root records. Copy captures only the transitive declared root-record dependency closure at Copy time, including cycles once. It ignores unresolved references and unrelated root records. Local Paste and cross-window HASH clipboard Paste both clone the captured closure into new root record IDs, even if the original source has since changed or a new scene has been opened. Multiple copied owners share the same imported root mapping.

Full HASH Merge imports all incoming root records with fresh IDs on each operation. The existing plugin/material/tag reference mapper is unchanged; author-data owner references get a separate transient object-only map so material/tag IDs cannot masquerade as object owners. Incoming missing root references are retained with `unresolved:true`, preventing coincidental binding to an unrelated destination root record of the same ID. External object references are intentionally retained as exact canonical native hashes: they resolve only if that exact owner exists in the destination. Unsupported field keys are retained and report `unsupported-field`.

Root union validation precedes geometry allocation and is repeated at publication. Native copy history captures/restores root author data with its copied objects; root restoration does not rewind Docs. Merge rollback restores its scoped root change only if publication occurred in the same scene. Native failures after a committed edit follow the existing API's commit/settlement behavior; a rejected post-settlement is not a general rollback of arbitrary plugin effects. For these new writes, a failure after the handler completed is explicitly `AUTHORING_POST_SETTLE_FAILED` with `completed:true` and its epoch-tagged `receipt` (also exposed in RPC structured content). Reread current epoch/revision before retrying; do not blindly repeat a mutation. Earlier failures inside native commit plumbing are not a universal rollback guarantee either.

## Shared API, not Control-specific fields

The shared commands live in the ordinary `frameAI` registry and are discovered by existing MCP adapters:

- `authorData.get {owner}` returns `{epoch,owner,data,runtime:'unavailable'}`.
- `authorData.inspect {owner}` adds `{references:[{record,index,ref,status}]}`. Status is `available`, `missing-owner`, `ambiguous-owner`, `missing-record`, `unsupported-field`, or `unresolved-reference`. Inspection uses a transient per-request owner index and per-owner record sets, never a persistent shadow registry or geometry readback.
- `authorData.replace {owner,expected:{epoch,revision},records}` validates the entire envelope/record revisions before one native editor transaction. Supplying unchanged records is a no-op with no new revision or Undo entry.
- `fields.list {owner}` lists the covered metadata and discoverable current parameter descriptors/values.
- `fields.read {owner,field}` reads a covered field.
- `fields.write {writes:[{owner,field,value,epoch,revision}]}` validates all targets and values before one native transaction. Duplicate targets reject; a wholly unchanged batch is a no-op. Selection is not changed.

The writable common field contract covers only `name` and `visible` on ordinary native owners, including inactive preserved owners. `name` is a string, writable length 4096 code units, no NUL or malformed Unicode. `visible` is the native authored boolean, not effective visibility after parent/Solo/enabled evaluation. Both have `unit:null`, `access:'read-write'`, `phase:'authoring'`, exact native owner hash, stable key independent of display name, availability, value, epoch and revision. Native UI rename/visibility and `scene.update` share these validators; ordinary native checkpoints own their Undo. Existing commands are not rerouted through a second field implementation.

Field `revision` is deliberately a conservative shared runtime native metadata transaction generation, not a persisted per-field counter. Any native metadata commit/publication can invalidate a field CAS, including unrelated edits. This avoids per-object tracking and catches A→B→A, hardware auto-naming and native reconstruction. Epoch resets fence restoration/replacement before asynchronous history work, including loading the same HASH again. Persisted source/container revisions may rewind under Undo, but old requests cannot regain validity by matching content. A successful mutation result is an epoch-tagged commit receipt; existing post-settlement may allow subsequent scene changes before its promise resolves.

Native authoring readiness starts false. Disposing the authoritative scene or beginning any document replacement invalidates its epoch and readiness before releasing/publishing state. Only the actual native scene-install listener marks authoring ready after rebuilding owners, hierarchy, materials and Docs. A listener failure (including DOM-dispatched exceptions) leaves inspection/mutation unavailable until a successful Open/New recovery. Pre-disposal validation failure/cancellation leaves the prior installed document intact. Initial startup and identical HASH reopen use the same completion path. Native Open and public `scene.new`/`scene.open` share the existing replacement-admission queue drain when the document is null, errored or uninstalled. Healthy operations keep ordinary settlement. Save/Merge and all ordinary commands reject an incomplete nonnull document; only an explicitly requested replacement can recover it. Busy native IO still rejects competing operations.

Only new read-only commands bypass the registry's pre/post global `settle`. They stay on the existing FIFO and reject during native IO, active history/authoring operations or gestures. Inputs are cloned with descriptor checks before generic validation in direct and RPC entry paths. Writes retain existing native pre/post settlement, then recheck live-scene/busy/CAS state immediately before effects. Thus reads do not activate plugins or force GPU work; writes can be blocked by an unrelated installed plugin's settlement failure. Stored source is never executed in either path.

Out of scope: local/world transforms, animation/evaluated writes, materials, parameter writes, nonscalar parameters, custom attribute fields, actions, element identities, Atomic internals, bulk typed transport, subscriptions, managed source execution, runtime ownership, lifecycle, author-selected autostart, panel windows and HTML rendering. Atomic ID nonreuse remains a separate prerequisite for persistent element bindings.

## Read-only scalar parameter observations

fields.list and fields.read additionally expose scalar number/boolean/string and string/number enum keys from the existing native definitions tuple, including static lazy-plugin manifests already installed in definitions. No schema registry, plugin activation, default fill, GPU readback, history or selection change is introduced. Preserved unknown-plugin owners do not borrow their placeholder native type schema. Object references are excluded by the native object key and FramePlugins.referenceField. Stable keys are param:<exact key>, preserving case, spaces and colons. The 128-code-unit field ID limit leaves 122 code units after the six-character param: prefix.

Parameter descriptors have access read-only, phase current, revision null, unit null and unitKnown false. observedFrame is only the current timelineFrame context; it is not evidence that simulation or evaluation completed. schemaAvailable and runtimeLoaded are distinct from availability. An unloaded plugin can have readable installed metadata and a current stored scalar without any runtime load. Missing and invalid own data values return missing-value or invalid-value and omit value, never substitute the schema default. Descriptor accessors are not evaluated. Parameter writes reject before any batch mutation; name/visible retain their existing authoring CAS and writable semantics.

fields.readBatch accepts {reads:[{owner,field}],epoch?}, with 1–128 requests. Canonical object hashes and bounded well-formed field strings are required. An optional stale epoch rejects the whole call. Malformed requests, native IO/busy state and incomplete document readiness reject the whole call through the ordinary data-tool FIFO. One synchronous observation captures epoch and observedFrame, builds one transient owner index, and returns {epoch,observedFrame,items:[...]} in request order, retaining duplicates. Items report available, missing-owner, ambiguous-owner, unsupported-field, missing-value or invalid-value. Unavailable items omit value. authorData.inspect uses the identical field descriptor resolver for typed parameter reference status.

Bounds: 512 total descriptors per list, 128 enum choices, 16,384 UTF-16 code units per scalar/choice string, 8,192 aggregate JSON values and 262,144 UTF-8 JSON bytes per list/read/batch response. Unsupported schema shapes are not exposed; oversized/invalid current values are unavailable. Aggregate response overflow rejects with LIMIT_EXCEEDED rather than truncating, even when request count is valid. No units, ranges or completion guarantees are guessed.

The separate tests/scene-parameter-layer.json reverses this extension to the frozen data-only runtime before tests/scene-data-layer.json reverses to main. tests/scene-parameters.mjs executes shipped definitions, real manifest JSON, native reference classifiers and the registry with CPU fixtures. Browser/GPU gates remain independently required.

## Document-lifetime owner reservation ledger

Exact native owner hashes retain a bounded allocation set when owners disappear through Undo, Delete or native history. The ledger stores only author-record identities, not a scene model. Restored owner envelopes union those identities into retired IDs, excluding IDs restored live; subsequent native HASH saves persist that envelope. A trusted restoration can revive the original record. Fresh-CAS creation cannot reuse an allocated ID even after its owner disappeared and returned. Epoch reset and scene-install readiness fencing preserve the ledger; only authoritative document replacement clears it.

Capacity is 4,096 namespaces (including scene when used), 65,536 allocated IDs per document and 4,608 allocated IDs per owner (at most 512 live plus 4,096 retired). Restored envelopes still enforce their 4,096 retired-ID limit. Pure preflight plans do not reserve IDs or modify caller snapshots. UI/native history validates combined root/owner plans before moving history stacks. Committed author edits, native record publication and successful installation register allocations. Duplicate and HASH Merge check aggregate capacity before geometry cloning/decoding, and native publication checks again. Fresh HASH preflight checks incoming aggregate capacity before replacement. Already-published native changes retain the existing documented non-universal rollback behavior.

The reservation fix is a third exact reversible layer, tests/scene-reservation-layer.json, above the parameter and data layers. tests/scene-reservations.mjs covers owner absence/restoration, native install and HASH persistence, explicit replacement reset, pure/failed preflights, document limits and pre-geometry Duplicate rejection.

## Native startup initialization seam

A freshly constructed native scene has no records Map until installNativeRecords publishes one. The attached author-data root reader treats that specific pre-install state as absent metadata, without creating records or marking the document ready. Root writes in that state reject NOT_READY. Already-bound native records use the unchanged read/write path. This allows reservation preflight before first native publication while preserving installation readiness fencing. The exact fourth reversal layer is tests/scene-startup-layer.json.
